# 6.11 HTTP Recorder

> **Spec chapter:** Record and replay Effect HTTP and WebSocket client traffic from deterministic JSON cassettes.
> **Parent:** [6 Components](../06-components.md)
> **Index:** [README.md](../README.md)

**File:** `packages/http-recorder/src/index.ts`, `packages/http-recorder/src/effect.ts`, `packages/http-recorder/src/socket.ts`

`@opencode-ai/http-recorder` ships a VCR-style layer for Effect 4 beta HTTP and WebSocket clients. Tests provide a cassette name; the layer records real upstream traffic locally or replays a committed JSON cassette without contacting the service. Application code does not branch on record versus replay.

## Construction / configuration

| Export / option | Default | Notes |
|-----------------|---------|-------|
| `HttpRecorder.http(name, options?)` | — | Returns a `Layer` providing `HttpClient.HttpClient` with fetch-backed recording/replay (`packages/http-recorder/src/effect.ts` `http`). |
| `HttpRecorder.socket(name, options?)` | — | Decorates a supplied `Socket.Socket` layer beneath it (`packages/http-recorder/src/socket.ts` `socket`). |
| `RecorderOptions.directory` | `<cwd>/test/fixtures/recordings` | Cassette root (`packages/http-recorder/src/cassette.ts` `DEFAULT_RECORDINGS_DIR`, `packages/http-recorder/src/types.ts` `RecorderOptions`). |
| `RecorderOptions.metadata` | omitted | Stored in cassette JSON metadata (`packages/http-recorder/src/types.ts` `RecorderOptions`). |
| `RecorderOptions.redact` | built-in defaults | Additive redaction policy (`packages/http-recorder/src/redactor.ts` `make`). |
| `RecorderOptions.match` | canonical JSON equality | Custom HTTP request matcher (`packages/http-recorder/src/matching.ts` `defaultMatcher`). |
| Package export `"."` | `./src/index.ts` | Public surface (`packages/http-recorder/package.json` `exports`). |
| Package export `"./internal"` | `./src/internal.ts` | Internal cassette, redactor, and test helpers (`packages/http-recorder/package.json` `exports`). |

Cassette files are named `<name>.json` under the recordings directory. Nested names such as `users/get-one` resolve to subdirectories (`packages/http-recorder/src/cassette.ts` `cassettePath`).

## Behavior

### Public API

The complete public API is `HttpRecorder.http` and `HttpRecorder.socket` (`packages/http-recorder/src/index.ts` `HttpRecorder`). Exported types are `CassetteMetadata`, `RecorderOptions`, `RedactOptions`, `RequestMatcher`, and `RequestSnapshot` (`packages/http-recorder/src/index.ts` `HttpRecorder` namespace).

### Record / replay mode selection

When mode is `auto` (the default for `HttpRecorder.http`), the layer resolves mode as follows (`packages/http-recorder/src/recorder.ts` `resolveAutoMode`, `packages/http-recorder/src/internal-effect.ts` `recordingLayer`):

| Condition | Mode |
|-----------|------|
| `CI` env set and not `""`, `"false"`, or `"0"` | `replay` |
| Cassette file exists | `replay` |
| Otherwise (local, missing cassette) | `record` |

In `record` mode the layer calls the upstream client, persists redacted request/response snapshots, and returns the live response (`packages/http-recorder/src/internal-effect.ts` `recordingLayer`). In `replay` mode it serves responses from the cassette without upstream I/O (`packages/http-recorder/src/internal-effect.ts` `recordingLayer`). A missing cassette under `CI=true` fails with a transport error whose description includes `Fixture "<name>" not found` (`packages/http-recorder/src/internal-effect.ts` `recordingLayer`).

There is no public overwrite mode; refreshing a cassette requires deleting its JSON file and rerunning the test locally (`packages/http-recorder/README.md` "Refresh A Cassette").

### HTTP request matching and ordering

Interactions are consumed strictly in cassette order: the first runtime request matches the first recorded interaction, the second matches the second, and so on (`packages/http-recorder/src/matching.ts` `selectSequential`). The default matcher canonicalizes JSON object keys and compares method, URL, headers, and body (`packages/http-recorder/src/matching.ts` `defaultMatcher`, `canonicalSnapshot`). A custom `match` function replaces the default equivalence check (`packages/http-recorder/src/types.ts` `RequestMatcher`).

Concurrent HTTP requests are serialized for append in request-start order even when responses complete out of order (`packages/http-recorder/src/internal-effect.ts` `recordingLayer` record branch with `Deferred` chain).

During replay, each claimed interaction is used exactly once; concurrent replay calls claim distinct indices (`packages/http-recorder/src/recorder.ts` `makeReplayState`).

Text responses are stored as strings; non-text bodies are stored as base64 with `bodyEncoding: "base64"` (`packages/http-recorder/src/internal-effect.ts` `captureResponseBody`). Status codes `204`, `205`, and `304`, and `HEAD` requests, reconstruct responses with a null body (`packages/http-recorder/src/internal-effect.ts` `responseFromSnapshot`).

### Redaction

Built-in redaction runs before persistence (`packages/http-recorder/src/redactor.ts` `make`). Header snapshots keep only allow-listed names; all other incoming header names are omitted (`packages/http-recorder/src/redaction.ts` `redactHeaders` filter step). A header value becomes `[REDACTED]` only when its name is both allow-listed and present in the redact set (`packages/http-recorder/src/redaction.ts` `redactHeaders` map step).

| Policy | Default coverage |
|--------|------------------|
| Request header allow-list | `content-type`, `accept`, `openai-beta`, plus `RedactOptions.allowRequestHeaders` and any name listed in `RedactOptions.headers` (`packages/http-recorder/src/redactor.ts` `DEFAULT_REQUEST_HEADERS`, `make`) |
| Response header allow-list | `content-type`, plus `RedactOptions.allowResponseHeaders` and any name listed in `RedactOptions.headers` (`packages/http-recorder/src/redactor.ts` `DEFAULT_RESPONSE_HEADERS`, `make`) |
| Header redact set when `RedactOptions.headers` is set | Caller-named headers plus defaults such as `authorization`, `cookie`, `x-api-key`, `x-goog-api-key` (`packages/http-recorder/src/redaction.ts` `DEFAULT_REDACT_HEADERS`, `redactionSet`) |
| Default sensitive headers (e.g. `authorization`) | Omitted from snapshots because they are not on the default allow-list (`packages/http-recorder/test/record-replay.test.ts` `extends default header redaction and allow lists`) |
| URL query parameters redacted | `access_token`, `api_key`, `apikey`, `key`, `token`, `signature`, AWS SigV4 params, and related names; matching values are set to `[REDACTED]` and serialized by `URL.toString()` as `%5BREDACTED%5D` (`packages/http-recorder/src/redaction.ts` `DEFAULT_REDACT_QUERY`, `redactUrl`, `packages/http-recorder/test/record-replay.test.ts` `redacts sensitive URL query parameters`) |
| URL credentials | When `url.username` or `url.password` is present, `redactUrl` assigns the `REDACTED` constant (`"[REDACTED]"`) to that field, then returns `URL.toString()`, which percent-encodes the userinfo as `%5BREDACTED%5D` (not a literal `[REDACTED]` substring) (`packages/http-recorder/src/redaction.ts` `redactUrl`, `packages/http-recorder/test/record-replay.test.ts` `redacts URL credentials`) |
| JSON body fields redacted | `access_token`, `api_key`, `password`, `secret`, `token`, and related normalized keys (`packages/http-recorder/src/redactor.ts` `DEFAULT_REDACT_JSON_FIELDS`) |

`RedactOptions.headers` names headers for both allow-list extension and redaction; allow-listed redact names persist as `[REDACTED]` (`packages/http-recorder/src/types.ts` `RedactOptions`, `packages/http-recorder/test/record-replay.test.ts` `extends default header redaction and allow lists`). Other options add allow-lists, extra query parameter names, extra JSON field names, and optional `url` / `body` transforms applied after built-in redaction (`packages/http-recorder/src/types.ts` `RedactOptions`).

Before writing, the recorder scans the full cassette (interactions plus metadata) for credential-like patterns and environment-variable secret values (`packages/http-recorder/src/redaction.ts` `secretFindings`, `packages/http-recorder/src/cassette.ts` `append`).

Mismatch diagnostics in replay errors use redacted snapshots; raw secrets are not echoed (`packages/http-recorder/src/matching.ts` `requestDiff`, `safeText`).

### WebSocket recording and replay

`HttpRecorder.socket` wraps an upstream `Socket.Socket` supplied beneath the layer. The public layer passes `{ url: "" }` into the recorder and sets `compareClientMessagesAsJson: true` (`packages/http-recorder/src/socket.ts` `socket`). Recorded cassettes therefore store an empty `open.url`; the upstream WebSocket URL is not duplicated in recorder configuration (`packages/http-recorder/test/record-replay.test.ts` `the public socket decorator replays a provided Effect socket`).

WebSocket cassettes store one interaction per connection with an `open` snapshot (URL and headers) and an ordered `events` transcript of client and server text or binary frames (`packages/http-recorder/src/schema.ts` `WebSocketInteractionSchema`). Text frames receive the same JSON/body redaction as HTTP; binary frames are stored losslessly as base64 (`packages/http-recorder/src/socket.ts` `encodeEvent`, `redactEvent`).

During replay, server frames are delivered until the next recorded client frame; replay then waits for the application to send a matching client frame before continuing (`packages/http-recorder/src/socket.ts` `runReplay`). Message handlers for server frames may run concurrently (`packages/http-recorder/src/socket.ts` `runReplay` with `FiberSet`).

Failed or interrupted live WebSocket runs do not write a complete cassette file (`packages/http-recorder/src/socket.ts` `makeRecordingSocket` exit handler). Concurrent runs of the same recorded or replayed WebSocket are rejected (`packages/http-recorder/src/socket.ts` `makeRecordingSocket`, `makeReplaySocket`).

### Cassette format

Cassettes are JSON version `1` with optional metadata and an ordered `interactions` array mixing HTTP and WebSocket entries (`packages/http-recorder/src/schema.ts` `CassetteSchema`). Metadata includes `name` and `recordedAt` ISO timestamp plus any caller metadata (`packages/http-recorder/src/cassette.ts` `buildCassette`).

File writes use a temporary file and atomic rename (`packages/http-recorder/src/cassette.ts` `append`).

### Known limits

- Responses are fully buffered during record and replay; streaming timing, cancellation, and backpressure are not modeled (`packages/http-recorder/README.md` "Current Limits").
- WebSocket replay preserves frame chronology and content, not network timing or backpressure (`packages/http-recorder/README.md` "Current Limits").
- WebSocket V1 cassettes do not reproduce terminal close codes, close reasons, or transport failures (`packages/http-recorder/README.md` "Current Limits").
- Cassette format version `1` has no migration tooling (`packages/http-recorder/README.md` "Current Limits").

## Error handling

| Error / condition | Behavior |
|-------------------|----------|
| Missing cassette in replay (including `CI=true`) | `HttpClientError` transport error; description includes `Fixture "<name>" not found` (`packages/http-recorder/src/internal-effect.ts` `recordingLayer`). |
| Request mismatch during replay | `HttpClientError` transport error; description includes `does not match the current request` and redacted diff lines (`packages/http-recorder/src/internal-effect.ts` `recordingLayer`, `packages/http-recorder/src/matching.ts` `requestDiff`). |
| More runtime requests than recorded interactions | Failure with detail `interaction N of M not recorded` (`packages/http-recorder/src/matching.ts` `selectSequential`). |
| Unused recorded interactions at scope end | Scope finalizer is a no-op when no interaction was claimed (`used === 0`). When at least one interaction was claimed but fewer than recorded, the finalizer fails the effect via `Effect.die` with `Unused recorded interactions in <name>: used N of M` (`packages/http-recorder/src/recorder.ts` `makeReplayState` finalizer). |
| `UnsafeCassetteError` | Append fails; HTTP record path maps to transport error with `contains possible secrets` (`packages/http-recorder/src/cassette.ts` `UnsafeCassetteError`, `packages/http-recorder/src/internal-effect.ts` `recordingLayer`). |
| Invalid cassette name (absolute, `..`, empty) | Synchronous `Error: Invalid cassette name` (`packages/http-recorder/src/cassette.ts` `cassettePath`). |
| WebSocket close with unconsumed events | Dies with `WebSocket closed with unconsumed events` (`packages/http-recorder/src/socket.ts` `runReplay`, `writer`). |
| WebSocket frame mismatch | Throws with `WebSocket event N: expected …, received …` (`packages/http-recorder/src/socket.ts` `assertEvent`). |
| Error-path HTTP requests | `redactedErrorRequest` strips headers, params, and body from error-carrying requests (`packages/http-recorder/src/internal-effect.ts` `redactedErrorRequest`). |
| Failed unsafe append (memory backend) | Prior interactions remain unchanged (`packages/http-recorder/src/cassette.ts` `memory` `append`). |

Tagged errors exported from the internal surface include `CassetteNotFoundError` and `UnsafeCassetteError` (`packages/http-recorder/src/cassette.ts`).
