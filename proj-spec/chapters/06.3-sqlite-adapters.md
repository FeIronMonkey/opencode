# 6.3 SQLite adapters

> **Spec chapter:** Shipped Effect SQLite client and Drizzle Effect SQLite adapter packages
> **Parent:** [6 Components](../06-components.md)
> **Index:** [README.md](../README.md)

**Retrospective:** this chapter describes current shipped behavior. It does not record historical approvals and does not require product refactors.

**Files:**

- `packages/effect-drizzle-sqlite/` (`@opencode-ai/effect-drizzle-sqlite`)
- `packages/effect-sqlite-node/` (`@opencode-ai/effect-sqlite-node`)

These two packages are one persistence concern: a generic Drizzle-on-Effect SQLite adapter plus a Node `node:sqlite` `SqlClient` implementation. Domain tables, OpenCode storage APIs, and Core wiring belong in [6.2 Core](06.2-core.md). The chapter map records 6.3 as consumed by 6.2 (`tmp/executive/opencode-retrospective-spec/findings/T1-chapter-map.md` §6).

## Construction / configuration

Package `AGENTS.md` for the Drizzle adapter states the package MUST stay generic (Drizzle + Effect + SQLite only) and MUST NOT add OpenCode-specific tables, paths, migrations, post-commit hooks, or domain storage APIs. Runtime adapter code should depend on generic `effect/unstable/sql/SqlClient`, not a concrete SQLite driver. Concrete clients such as `@effect/sql-sqlite-bun` belong in tests or examples unless a driver-specific helper is added (`packages/effect-drizzle-sqlite/AGENTS.md`).

Both packages are private MIT workspace packages, `"type": "module"`, version `1.18.30` (`packages/effect-drizzle-sqlite/package.json`, `packages/effect-sqlite-node/package.json`).

### Node SQLite client

`NodeSqliteClient.make` and `NodeSqliteClient.layer` take `SqliteClientConfig` (`packages/effect-sqlite-node/src/index.ts` `SqliteClientConfig`, `make`, `layer`).

| Parameter | Default / required | Notes |
|-----------|--------------------|-------|
| `filename` | required | Passed to `node:sqlite` `DatabaseSync` |
| `readonly` | optional | Mapped to `DatabaseSync` `readOnly`. When `true`, WAL pragma is skipped |
| `timeout` | optional | Passed to `DatabaseSync` |
| `allowExtension` | optional | Passed to `DatabaseSync` |
| `disableWAL` | optional | When not `true` **and** `readonly` is not `true`, `make` runs `PRAGMA journal_mode = WAL;` |
| `spanAttributes` | optional | Extra span attribute entries; `make` always also sets `db.system.name` = `"sqlite"` |
| `transformResultNames` | optional | When set, row transforms use `Statement.defaultTransforms(...).array` |
| `transformQueryNames` | optional | Passed to `Statement.makeCompilerSqlite` |
| `create` | declared, unused by `make` | Present on `SqliteClientConfig`; not passed to `DatabaseSync` |
| `readwrite` | declared, unused by `make` | Present on `SqliteClientConfig`; not passed to `DatabaseSync` |

`DatabaseSync` is always constructed with `open: true` and `enableForeignKeyConstraints: true`. The connection is closed on Effect finalizer (`db.close()`). Access is serialized with a semaphore of size `1`. `layer` provides the client as both `SqliteClient` and `Client.SqlClient`, and provides `Reactivity.layer`.

### Drizzle Effect database

`EffectDrizzleSqlite.make` (Effect span name `SQLiteDrizzle.make`) requires Effect services `SqlClient`, `EffectCache`, and `EffectLogger` (`packages/effect-drizzle-sqlite/src/effect-sqlite/driver.ts` `make`). Config type `EffectDrizzleSQLiteConfig` is `DrizzleConfig` omitting `cache`, `logger`, and `schema`.

| Parameter | Default | Notes |
|-----------|---------|-------|
| `config` | `{}` | Optional. `relations` default to `{}`. `config.jit` is passed through `jitCompatCheck` into session `useJitMappers` |
| `DefaultServices` | `Layer.merge(EffectCache.Default, EffectLogger.Default)` | Used by `makeWithDefaults` |
| `makeWithDefaults(config)` | `make(config).pipe(Effect.provide(DefaultServices))` | Caller still MUST provide `SqlClient` |

`make` constructs `SQLiteAsyncDialect`, `EffectSQLiteSession`, and `EffectSQLiteDatabase`, then sets `db.$client` to the yielded `SqlClient` and `db.$cache.invalidate` to `cache.onMutate`.

`jitCompatCheck(isEnabled)` returns `false` when `isEnabled` is falsy; when truthy it returns whether `new Function(...)` can run (`packages/effect-drizzle-sqlite/src/internal/drizzle-utils.ts` `jitCompatCheck`).

Every test in `packages/effect-drizzle-sqlite/test/sqlite.test.ts` constructs the database with `EffectDrizzleSqlite.makeWithDefaults()`. `selects rows through Effect-yieldable query builders`, `commits successful transactions`, `rolls back failed transactions`, `rolls back explicit transaction rollback`, and `supports returning and rejects empty update sets` go through helper `makeDb` (which also `create table users`). `preserves failed transaction begin errors` and `runs migrations once and records migration metadata` call `makeWithDefaults()` directly; the latter also skips `makeDb`’s `create table users`.

## Behavior

Root barrel `packages/effect-drizzle-sqlite/src/index.ts` re-exports `EffectLogger` from `drizzle-orm/effect-core`, `make` / `makeWithDefaults` / session types from `./effect-sqlite/driver` and `./effect-sqlite/session`, `migrate` from `./effect-sqlite/migrator`, and namespace `EffectDrizzleSqlite`.

### Node client operations

`SqliteClient` extends Effect `SqlClient` and adds `config`, `loadExtension`, TypeId `~@opencode-ai/effect-sqlite-node/NodeSqliteClient`, and `updateValues: never` (`packages/effect-sqlite-node/src/index.ts`).

| Method | Behavior |
|--------|----------|
| `execute` / `executeRaw` / `executeUnprepared` | Prepare SQL, apply `Client.SafeIntegers` via `statement.setReadBigInts`, run `statement.all`. `execute` optionally maps rows with `transformRows` |
| `executeValues` | Same prepare path with `setReturnArrays(true)` |
| `executeStream` | `Stream.die("executeStream not implemented")` |
| `loadExtension(path)` | `db.loadExtension(path)` wrapped in `Effect.try` |

### Drizzle query surface

`SQLiteEffectDatabase` in `packages/effect-drizzle-sqlite/src/sqlite-core/effect/db.ts` exposes Drizzle-style builders (`select`, `insert`, `update`, `delete`, raw/`run`/`all`/`get`/`values`, `$count`, `$with`/`with`, `query`, `transaction`). `db.ts` also exports standalone `withReplicas`. It does not call `applyEffectWrapper`.

Builders become Effect-yieldable via `applyEffectWrapper` on the builder classes in `packages/effect-drizzle-sqlite/src/sqlite-core/effect/select.ts`, `insert.ts`, `update.ts`, `delete.ts`, `raw.ts`, `count.ts`, and `query.ts`.

| Method / command | Behavior |
|------------------|----------|
| `select` / `selectDistinct` | `SQLiteEffectSelectBuilder`; distinct when `selectDistinct` or `with(...).selectDistinct` |
| `insert` / `update` / `delete` | Corresponding Effect builders on a `SQLiteTable` |
| `$count(source, filters?)` | Count query; mapper treats numeric first cell as-is, otherwise `Number(v)` or `0` (`count.ts` `execute`) |
| `$with` / `with(...)` | CTE helpers; `with` returns `{ select, selectDistinct, update, insert, delete }` bound to the CTE list |
| `run` / `all` / `get` / `values` | Raw SQL or `SQLWrapper` via `SQLiteEffectRaw` and session execute methods |
| `query[relationName]` | `SQLiteEffectRelationalQueryBuilder` with `findMany` / `findFirst` when `relations` were passed to `make` |
| `transaction(fn, config?)` | Delegates to `EffectSQLiteSession.transaction` |

Standalone `export const withReplicas` in `packages/effect-drizzle-sqlite/src/sqlite-core/effect/db.ts` (not a `SQLiteEffectDatabase` method) wraps a primary database and at least one replica: reads (`select`, `selectDistinct`, `$count`, `$with`, `with`, `query`) use `getReplica` (default: uniform random replica). Writes, raw execute, and `transaction` use `primary`.

`EffectSQLiteSession.execute` uses `client.unsafe(query.sql, params)`: `values` → `.values`; `get` → first row of `.withoutTransform`; otherwise `.withoutTransform` (`packages/effect-drizzle-sqlite/src/effect-sqlite/session.ts` `execute`).

Prepared queries log SQL through `EffectLogger.logQuery`, then apply Effect cache strategy (`skip` / `invalidate` / `try`) unless the cache is `NoopCache`. In-transaction selects with cache enabled skip cache lookup/put (`packages/effect-drizzle-sqlite/src/sqlite-core/effect/session.ts` `queryWithCache`).

### Transactions

`EffectSQLiteSession.withTransaction` (`packages/effect-drizzle-sqlite/src/effect-sqlite/session.ts`):

| Case | SQL |
|------|-----|
| Outermost begin | `begin ${config?.behavior ?? "deferred"}` |
| Nested begin | `savepoint effect_sql_${id}` (`id` increments per nested `transactionService` depth) |
| Outermost success | `commit` |
| Nested success | `release savepoint effect_sql_${id}` |
| Outermost failure | `rollback` |
| Nested failure | `rollback to savepoint effect_sql_${id}` then `release savepoint effect_sql_${id}` |

If outermost `commit` fails, the session runs `rollback` (ignoring rollback errors) and fails with the commit error. Nested work reuses a reserved connection from `client.transactionService` when already in a transaction; otherwise it `reserve`s a connection in a new scope.

`SQLiteEffectTransaction.rollback()` returns `new EffectTransactionRollbackError()` (`packages/effect-drizzle-sqlite/src/sqlite-core/effect/session.ts` `rollback`). Tests fail the Effect with that value to roll back (`test/sqlite.test.ts` `rolls back explicit transaction rollback`).

### Migrations

`EffectDrizzleSqlite.migrate(db, config)` reads files with Drizzle `readMigrationFiles(config)` and runs `sqlite-core/effect/session.ts` `migrate` (`packages/effect-drizzle-sqlite/src/effect-sqlite/migrator.ts`).

| Parameter | Default | Notes |
|-----------|---------|-------|
| `config.migrationsFolder` | required by `readMigrationFiles` | Folder of timestamped migration dirs with `migration.sql` (see `test/sqlite.test.ts` `createMigrationsFolder`, `examples/migrations/`) |
| `config.migrationsTable` | `"__drizzle_migrations"` | Public `EffectDrizzleSqlite.migrate` takes `MigrationConfig`, not a string (`packages/effect-drizzle-sqlite/src/effect-sqlite/migrator.ts` `migrate`). Internal `session.ts` `migrate` resolves the table as `typeof config === "string" ? "__drizzle_migrations" : (config.migrationsTable ?? "__drizzle_migrations")` — a string `config` does **not** become the table name |
| `config.init` | unset | Special path; see error handling |

On first use (`upgradeIfNeeded` reports `newDb: true`), `migrate` creates:

```sql
CREATE TABLE IF NOT EXISTS <migrationsTable> (
  id INTEGER PRIMARY KEY,
  hash text NOT NULL,
  created_at numeric,
  name text,
  applied_at TEXT
)
```

(`packages/effect-drizzle-sqlite/src/sqlite-core/effect/session.ts` `migrate`). Pending migrations from `getMigrationsToRun` run inside `session.transaction`: each SQL statement via `tx.run(sql.raw(stmt))`, then an insert of `hash`, `created_at`, `name`, `applied_at` (`new Date().toISOString()`). A second `migrate` with the same folder does not re-apply; tests expect one `__drizzle_migrations` row named `20240101000000_create_migrated_users` (`runs migrations once and records migration metadata`).

If the migrations table already exists without a `name` column, `upgradeIfNeeded` treats version as `0` and runs `upgradeFromV0` (backfill then statements) (`packages/effect-drizzle-sqlite/src/up-migrations/effect-sqlite.ts`, `utils.ts` `GET_VERSION_FOR.sqlite`, `MIGRATIONS_TABLE_VERSIONS.sqlite` = `1`). Missing upgrade functions fail with `EffectDrizzleError` message `No upgrade path from migration table version ${v} to ${v + 1}`.

## Error handling

| Situation | Behavior |
|-----------|----------|
| Node statement / extension failure | `SqlError` with `reason` from `classifySqliteError` (`packages/effect-sqlite-node/src/index.ts`). Execute uses `message: "Failed to execute statement"`, `operation: "execute"`. Load extension uses `message: "Failed to load extension"`, `operation: "loadExtension"` |
| Locked DB on `begin immediate` | `SqlError` with `reason._tag` `LockTimeoutError` when the cause message contains `database is locked` (`test/sqlite.test.ts` `preserves failed transaction begin errors`) |
| Failed query inside prepared-query cache path | Wrapped as `EffectDrizzleQueryError` with `query`, `params`, and `Cause.fail(e)` (`session.ts` `queryWithCache`) |
| Failed transaction body | Session rolls back (or rolls back to savepoint); the original failure is preserved after finalize |
| `tx.rollback()` | Produces `EffectTransactionRollbackError`; used as a fail value to abort the transaction |
| Empty `update(...).set` (all values `undefined`) | Synchronous `Error` `"No values to set"` (`drizzle-utils.ts` `mapUpdateSet`; test `supports returning and rejects empty update sets`) |
| `insert(...).values([])` | Synchronous `Error` `"values() must be called with at least one value"` (`insert.ts` `values`) |
| Insert-select column mismatch | Synchronous `Error` `"Insert select error: selected fields are not the same or are in a different order compared to the table definition"` (`insert.ts` `select`) |
| `onConflictDoUpdate` with both `where` and `targetWhere`/`setWhere` | Synchronous `Error` `'You cannot use both "where" and "targetWhere"/"setWhere" at the same time - "where" is deprecated, use "targetWhere" or "setWhere" instead.'` (`insert.ts` `onConflictDoUpdate`) |
| Duplicate update join alias | Synchronous `Error` ``Alias "${tableName}" is already used in this query`` (`update.ts`) |
| Execute select built without a session | Synchronous `Error` `"Cannot execute a query on a query builder. Please use a database instance instead."` (`select.ts` `_prepare`) |
| `config.init` and DB already has migration rows | `MigratorInitError` `{ exitCode: "databaseMigrations" }` |
| `config.init` and local migrations length `> 1` | `MigratorInitError` `{ exitCode: "localMigrations" }` |
| Migration table upgrade / DB rows with no matching local file (Effect `migrate`) | `prepareSQLiteMigrationBackfill` throws `unmatchedMigrationError` (`Error` in `packages/effect-drizzle-sqlite/src/up-migrations/sqlite.ts`) when applied DB migration rows do not match any local migration. Effect `upgradeFromV0` wraps that throw with `Effect.try` + `migrationUpgradeError`, so the Effect fails with `EffectDrizzleError`, not the raw `Error` (`packages/effect-drizzle-sqlite/src/up-migrations/effect-sqlite.ts` `upgradeFromV0`, `migrationUpgradeError`) |
| Missing migration-table upgrade function | `EffectDrizzleError` message `No upgrade path from migration table version ${v} to ${v + 1}` (`effect-sqlite.ts` `upgradeIfNeeded`) |
| `executeStream` | Fiber death with `"executeStream not implemented"` |
