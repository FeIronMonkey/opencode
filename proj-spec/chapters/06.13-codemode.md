# 6.13 CodeMode

> **Spec chapter:** Effect-native confined JavaScript execution over explicit, schema-described tools.
> **Parent:** [6 Components](../06-components.md)
> **Index:** [README.md](../README.md)

**File:** `packages/codemode/` (`@opencode-ai/codemode`, private workspace package)

CodeMode lets a host expose a nested tool tree to a model-authored JavaScript program. Programs may sequence tool calls, transform plain data, branch, loop, and run independent calls in parallel. They receive no ambient filesystem, process, network, module, or application authority beyond the supplied `tools` tree. The primary CLI host consumes this package (see [6.1 Agent CLI](06.1-agent-cli.md)); CodeMode itself is unaware of host session, channel, or conversation models (`packages/codemode/AGENTS.md`).

Public exports (`packages/codemode/src/index.ts`): `CodeMode`, `Tool`, `OpenAPI`, `ToolError`, `toolError`.

| Surface | Role | Source |
|---------|------|--------|
| `CodeMode.execute(options)` | One-shot execution without a reusable runtime | `packages/codemode/src/codemode.ts` `execute` |

### `CodeMode.execute` options

| Parameter | Default | Notes |
|-----------|---------|-------|
| `code` | — | Required; source in the supported JS subset |
| `tools` | `{}` | Nested tree exposed as `tools` in programs; validated by `ToolRuntime.assertValidTools` |
| `limits.timeoutMs` | none (no timeout) | Safe integer ≥ 1 when set |
| `limits.maxToolCalls` | none (unlimited) | Safe integer ≥ 0 when set |
| `limits.maxOutputBytes` | none (no truncation) | Safe integer ≥ 0 when set; host policy, not library default |
| `onToolCallStart` | none | Effect hook after input decode, before tool run; must not fail |
| `onToolCallEnd` | none | Effect hook when an admitted call settles; interrupted calls emit no end event |

(`packages/codemode/src/codemode.ts` `ExecuteOptions`, `ExecutionLimits`; `packages/codemode/src/tool-runtime.ts` `ToolCallHooks`)

### `CodeMode.make` options

Extends execute options (minus `code`) with discovery configuration:

| Parameter | Default | Notes |
|-----------|---------|-------|
| `tools` | `{}` | Same as `execute` |
| `limits.*` | none | Same as `execute` |
| `discovery.catalogBudget` | `2000` | Estimated tokens (`chars / 4`) for inlined catalog signatures; non-negative safe integer; passed to `ToolRuntime.prepare` |
| `onToolCallStart` / `onToolCallEnd` | none | Same as `execute` |

(`packages/codemode/src/codemode.ts` `Options`, `DiscoveryOptions`; `packages/codemode/src/tool-runtime.ts` `defaultCatalogBudget`, `prepare`)

Invalid limit values throw `RangeError` at `make`/`execute` time (`packages/codemode/src/codemode.ts` `validateLimit`). Explicit `undefined` for a limit field is equivalent to leaving it unset.

The Effect environment type is inferred from tool `run` implementations; CodeMode does not erase service requirements (`packages/codemode/src/codemode.ts` `Services` via `tool-runtime.ts` `ServicesOf`).

### `Tool.make` options

| Parameter | Required | Notes |
|-----------|----------|-------|
| `description` | yes | Model-visible tool contract |
| `input` | yes | Effect Schema (validated) or JSON Schema (render-only signature) |
| `output` | no | Same schema choices; omitted → model-visible `Promise<unknown>` signature (`describeDefinition` / `outputTypeScript`); host result exposed as-is |
| `run` | yes | `(input) => Effect`; receives decoded input for Effect Schemas |

(`packages/codemode/src/tool.ts` `Options`, `make`; `packages/codemode/src/tool-runtime.ts` `describeDefinition`; `packages/codemode/src/tool-schema.ts` `outputTypeScript`)

Effect Schema input is decoded before `run`; Effect Schema output is encoded from `run`, then decoded and copied before the program sees it. JSON Schema sides shape signatures only; values pass through unvalidated (`packages/codemode/src/tool.ts` docstring on `make`).

### `OpenAPI.fromSpec` options

| Parameter | Required | Notes |
|-----------|----------|-------|
| `spec` | yes | Parsed OpenAPI 3.x document; YAML must be parsed by the host |
| `baseUrl` | no | Overrides document, path, and operation `servers` when set |
| `auth.resolve` | no | Host-side credential resolution keyed by security scheme name |
| `headers` | no | Static headers on every request; not model-visible |

(`packages/codemode/src/openapi/types.ts` `Options`)

Returns `{ tools, skipped }` synchronously. Generated tools require `HttpClient.HttpClient` in the Effect environment (`packages/codemode/src/openapi/index.ts`, `packages/codemode/src/openapi/types.ts` `Tools`).

## Behavior

### Execution entrypoints

`CodeMode.execute({ ...options, code })` is equivalent to `CodeMode.make(options).execute(code)` (`packages/codemode/test/codemode.test.ts` `"keeps one-shot and reusable execution equivalent"`).

A reusable runtime exposes:

| Method | Returns |
|--------|---------|
| `catalog()` | Structured tool descriptions (path, description, TypeScript signature) |
| `instructions()` | Model-facing markdown: workflow, rules, language summary, budgeted tool catalog |
| `execute(code)` | `Effect<Result, never, R>` |

(`packages/codemode/src/codemode.ts` `Runtime`)

Program, validation, limit, and tool failures are returned as `CodeMode.Result` data (`ok: false` + `Diagnostic`); they do not fail the outer Effect. Host interruption remains interruption, not a `Failure` result (`packages/codemode/test/codemode.test.ts` `"CodeMode host failure boundary"`).

### Result shape

| Variant | Fields |
|---------|--------|
| `Success` (`ok: true`) | `value` (JSON-safe), optional `logs`, optional `truncated`, `toolCalls` |
| `Failure` (`ok: false`) | `error` (`Diagnostic`), optional `logs`, optional `truncated`, `toolCalls` |

(`packages/codemode/src/codemode.ts` `Success`, `Failure`, `Result`)

`toolCalls` lists `{ name }` for every admitted call in order, retained on failure for audit without exposing inputs or host failures (`packages/codemode/src/tool-runtime.ts` `ToolCall`, `recordCall`).

Successful program return values cross a plain-data boundary: `undefined` (including implicit end-of-program) becomes `null`; nested `undefined` normalizes to `null` (`packages/codemode/src/tool-runtime.ts` `copyOut`).

`CodeMode.Input`, `CodeMode.Result`, and related schemas are exported for host/agent-tool wiring (`packages/codemode/src/codemode.ts`).

### Tool tree and discovery

Hosts supply a nested object tree; leaf nodes are `Tool.make` definitions (tagged `CodeModeTool`). Programs access tools as `tools.namespace.tool(...)`.

| Rule | Behavior |
|------|----------|
| Reserved namespace | Host MUST NOT define top-level `$codemode`; reserved for runtime search (`packages/codemode/src/tool-runtime.ts` `reservedNamespace`, `assertValidTools`) |
| Search tool | Always registered at `tools.$codemode.search`; advertised in instructions only when catalog is partial |
| Catalog budget | Default 2000 estimated tokens; round-robin across namespaces by cheapest signature first |
| Instructions | Workflow → Rules → Language → Available tools; states COMPLETE vs PARTIAL coverage |

(`packages/codemode/src/tool-runtime.ts` `prepare`, `makeSearchTool`; `packages/codemode/test/codemode.test.ts` `"inlines a COMPLETE small catalog and keeps search registered but unadvertised"`)

Search input: optional `query`, `namespace`, `limit` (positive int, default 10), `offset` (non-negative, default 0). Output: `items` (path, description, signature), `remaining`, `next` pagination cursor (`packages/codemode/src/tool-runtime.ts` `SearchInput`, `SearchOutput`, `makeSearchTool`).

### Tool-call lifecycle

In `ToolRuntime.invoke` (`packages/codemode/src/tool-runtime.ts` `invoke`):

1. Each argument passes `copyOut(copyIn(...))` → `InvalidDataValue` on plain-data violation (depth, circularity, blocked properties, un-awaited promise, non-data values).
2. Path resolution via `resolve` → `UnknownTool` if missing or non-callable.
3. For schema-backed tools: arity check and `decodeToolInput` → `InvalidToolInput` on wrong argument count or schema decode failure.
4. `onToolCallStart` with decoded input.
5. Tool `run` Effect (host services available).
6. Output schema decode and `copyIn` on result via `decodeOutput` → `InvalidToolOutput` on failure (schema decode or copy throw).
7. `onToolCallEnd` with duration and `"success"` / `"failure"` outcome; model-safe `message` on failure.

Invoke-argument `copyIn` in the same `invoke` path, and final-result `copyIn` after the program returns, remain `InvalidDataValue`. A tool `run` is not invoked unless input decoded successfully. A tool result is not visible to the program unless output decoded and crossed the plain-data boundary (`packages/codemode/src/tool-runtime.ts` `make`, `decodeOutput`; `packages/codemode/README.md` Laws).

Host failures and defects are sanitized to `"Tool execution failed"` unless the tool fails with explicit `toolError(message)` (`packages/codemode/src/tool-runtime.ts` `runHost`; `packages/codemode/test/codemode.test.ts` `"sanitizes unknown host failures and defects"`).

### Execution limits (host policy)

| Limit | When exceeded |
|-------|----------------|
| `maxToolCalls` | `ToolCallLimitExceeded` diagnostic; call not admitted |
| `timeoutMs` | `TimeoutExceeded`; interrupts in-flight tool Effects and pure busy loops |
| `maxOutputBytes` | Does not fail; truncates serialized result and/or logs, sets `truncated: true` |

(`packages/codemode/src/interpreter/runtime.ts` `boundOutput`, timeout handling; `packages/codemode/src/tool-runtime.ts` `recordCall`; `packages/codemode/test/codemode.test.ts` `"CodeMode output budget"`)

Fixed internal constants (not configurable): at most **8** concurrent tool calls (`packages/codemode/src/stdlib/promise.ts` `TOOL_CALL_CONCURRENCY`); plain-data nesting depth at most **32** (`packages/codemode/src/tool-runtime.ts` `MAX_VALUE_DEPTH`).

### Confined JavaScript subset

Programs are transpiled with TypeScript, parsed with Acorn, and interpreted without `eval` (`packages/codemode/src/interpreter/runtime.ts` `parseProgram`).

Supported surface (non-exhaustive; see tests under `packages/codemode/test/`):

- Plain data, control flow, functions/closures, optional chaining, templates, spread, `try`/`catch`.
- Selected stdlib: arrays/strings/numbers, `Object`, `Math`, `JSON`, `Date`, `RegExp`, `Map`, `Set`, `URL`, `URLSearchParams`, URI encode/decode.
- First-class promises for tool calls: un-awaited calls start immediately; `await`, `Promise.all` / `allSettled` / `race`, `Promise.resolve` / `reject`.
- `console.log` / `warn` / `error` capture into result `logs`.

Unsupported syntax yields `UnsupportedSyntax` with source location when available (`packages/codemode/src/interpreter/model.ts` `unsupportedSyntax`; `packages/codemode/test/promise.test.ts` `"unsupported promise surface"`). Not available: `eval`, dynamic imports, modules, classes, generators, timers, host globals, prototype mutation, custom `new Promise`, promise chaining (`.then`/`.catch`/`.finally`) (`packages/codemode/src/tool-runtime.ts` `prepare` language section; `packages/codemode/README.md` Supported Programs).

At data boundaries (final result, tool arguments, `JSON.stringify`), sandbox value types serialize like `JSON.stringify` (Date/URL → strings; RegExp/Map/Set/URLSearchParams → `{}`); un-awaited promises are rejected with an await hint (`packages/codemode/src/tool-runtime.ts` `copyIn`).

### OpenAPI adapter

`OpenAPI.fromSpec` emits one tool per supported operation; unsupported operations append to `skipped` with a reason instead of producing broken tools (`packages/codemode/src/openapi/index.ts` `fromSpec`; `packages/codemode/AGENTS.md` OpenAPI rules).

| Concern | Behavior |
|---------|----------|
| Skipping | Unsupported parameter serialization, non-JSON bodies, binary/streaming responses, malformed security |
| Server URL | Operation/path servers precede document servers; `baseUrl` overrides all |
| Input shape | Path, query, header, and object-body fields flattened; cross-location name collisions prefixed (`path_`, `query_`, etc.) |
| Auth | Resolved host-side via `auth.resolve`; never model-visible; cookie auth alternatives discarded |
| HTTP errors | Non-2xx → `toolError` with status and size-capped body summary (max 1024 chars) |
| Response size | Rejected above 50 MiB |

(`packages/codemode/src/openapi/runtime.ts` `maxResponseBodyBytes`, `maxErrorBodyChars`, `invoke`; `packages/codemode/test/openapi.test.ts` `"OpenAPI.fromSpec"`)

Unresolved schema constructs render as `unknown` in generated signatures, never invented TypeScript names (`packages/codemode/AGENTS.md`).

### Authority split

| Host owns | CodeMode owns |
|-----------|---------------|
| Authentication, authorization, tool selection | Parsing/interpreting supported JS without `eval` |
| Credentials, network clients, persistence | Schema boundaries and plain-data copying |
| Logging/redaction policy | Resource limits, call accounting, diagnostics |
| Approval and durable side effects | Model-facing discovery and instructions |

(`packages/codemode/README.md` Authority Boundary; `packages/codemode/AGENTS.md`)

## Error handling

### Diagnostic kinds

| Kind | When produced | Source / test |
|------|---------------|---------------|
| `ParseError` | Empty source or TypeScript/Acorn parse failure | `packages/codemode/src/interpreter/runtime.ts` `parseProgram`, empty-code check |
| `UnsupportedSyntax` | Parsed JS outside supported subset | `packages/codemode/src/interpreter/model.ts` `unsupportedSyntax`; `packages/codemode/test/promise.test.ts` `"unsupported promise surface"` |
| `UnknownTool` | Tool path missing, non-callable, or unknown namespace | `packages/codemode/src/tool-runtime.ts` `resolve`, `namespaceKeys`; `packages/codemode/test/enumeration.test.ts` `"an unknown namespace is an UnknownTool error"` |
| `InvalidToolInput` | Wrong argument arity or Effect Schema input decode failure | `packages/codemode/src/tool-runtime.ts` `invoke`; `packages/codemode/test/codemode.test.ts` `"rejects invalid configuration and discovery limits"`, schema-decode case |
| `InvalidToolOutput` | Tool output failed schema decode (`invoke` / `decodeToolOutput`) or `copyIn` in `decodeOutput` | `packages/codemode/src/tool-runtime.ts` `decodeOutput`, `invoke`; `packages/codemode/test/codemode.test.ts` `"sanitizes invalid host output"`, `"sanitizes host output that throws while being copied"` |
| `InvalidDataValue` | Plain-data contract violation at invoke-argument or final-result `copyIn`, or in-program data rules | `packages/codemode/src/tool-runtime.ts` `copyIn`, `invoke`; `packages/codemode/src/interpreter/runtime.ts` execution-result `copyIn`; `packages/codemode/test/promise.test.ts` `"promises at data boundaries"`; `packages/codemode/test/enumeration.test.ts` `"Object.values/entries on a tool reference"` |
| `ToolCallLimitExceeded` | Admitted calls exceeded `maxToolCalls` | `packages/codemode/src/tool-runtime.ts` `recordCall`; `packages/codemode/test/codemode.test.ts` `"enforces the tool-call limit as a diagnostic"` |
| `TimeoutExceeded` | Exceeded `timeoutMs` | `packages/codemode/src/interpreter/runtime.ts` timeout handler; `packages/codemode/test/codemode.test.ts` timeout case; `packages/codemode/test/promise.test.ts` `"timeout interruption of forked calls"` |
| `ToolFailure` | Tool refused via `toolError` or sanitized host failure/defect | `packages/codemode/src/interpreter/runtime.ts` `normalizeError`; `packages/codemode/test/codemode.test.ts` `"CodeMode host failure boundary"` |
| `ExecutionFailure` | Program `throw`, uncaught runtime error, or non-Error thrown value | `packages/codemode/src/interpreter/runtime.ts` `normalizeError` (`ProgramThrow` → `ExecutionFailure`, `Uncaught: ${message}`); `packages/codemode/test/codemode.test.ts` `"keeps logs captured before failures"` (`Uncaught: boom`) |

`Diagnostic` may include `location` (`line`, `column`) and `suggestions` (`packages/codemode/src/codemode.ts` `Diagnostic`).

### Safe operational refusals

```ts
import { toolError } from "@opencode-ai/codemode"
Effect.fail(toolError("Order is unavailable"))
```

Only `message` is model-visible; optional `cause` is for host diagnostics and is not returned in `Result` (`packages/codemode/src/tool-error.ts` `ToolError`, `toolError`).

### Configuration errors (throw, not `Result`)

| Condition | Error |
|-----------|-------|
| Invalid limit integer | `RangeError` from `validateLimit` |
| Invalid `discovery.catalogBudget` | `RangeError` |
| Host defines `$codemode` namespace | `Error` from `assertValidTools` |

### Non-goals (out of package scope)

Generic permission prompts, durable pause/resume, exactly-once side effects, application authorization policy, full JavaScript/npm compatibility, and ambient host capabilities such as `fetch` (`packages/codemode/README.md` Non-Goals; `packages/codemode/AGENTS.md` Future Design Notes).
