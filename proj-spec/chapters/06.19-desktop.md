# 6.19 Desktop

> **Spec chapter:** Electron desktop shell that hosts the web app UI, spawns a local OpenCode backend, and exposes native OS integration.
> **Parent:** [6 Components](../06-components.md)
> **Index:** [README.md](../README.md)

**File:** `packages/desktop/` (runtime entry `src/main/index.ts`; packaged `main` path is [10.1 Install](10.1-install.md))

Retrospective spec (C8): describes shipped **runtime** of `@opencode-ai/desktop` (Electron main/preload/renderer, sidecar, updater, `AppInterface` mount). Desktop **packaging / install artifacts** (`package.json` `main`, electron-builder identities/channel/protocol/extraResources, `predev`/`prebuild`/`downloadCliToResources`) are **canonical** in [10.1 Install](10.1-install.md); this chapter **links only** those facts. `@opencode-ai/app` export trees (`DESKTOP_MENU`, `UpdaterState`, `appPlugin`, desktop-native i18n, routes) are **canonical** in [6.18 App](06.18-app.md); this chapter records consumption. Runtime `dependencies` include Electron helpers (`electron-context-menu`, `electron-log`, `electron-store`, `electron-updater`, `electron-window-state`) plus `effect`, `drizzle-orm`, and `@zip.js/zip.js` (`package.json`); workspace `@opencode-ai/app` / `@opencode-ai/ui` are `devDependencies` used at build time.

## Construction / configuration

### Package scripts

Packaging scripts `predev` / `prebuild` / `package` / `package:mac|win|linux` (Electron install, icon/metainfo copies, opencode node bundle, `downloadCliToResources`, electron-builder) are canonical in [10.1 Install](10.1-install.md).

| Script | Command | Notes |
|--------|---------|-------|
| `dev` | `electron-vite dev` | Local development (`package.json`) |
| `build` | `electron-vite build` | Compiles main/preload/renderer; packaged entry path `out/main/index.js` is [10.1 Install](10.1-install.md) |
| `typecheck` | `tsgo -b` | Typecheck (`package.json`) |
| `native:build` | `bun install --cwd native` | Native addon build (`package.json`) |

`electron-vite` bundles three processes: **main** (`src/main/index.ts`, `src/main/sidecar.ts`), **preload** (CJS `src/preload/index.ts`), **renderer** (Solid app rooted at `src/renderer`, Vite plugin **from** `@opencode-ai/app` — export SoT [6.18 App](06.18-app.md) `./vite`) (`electron.vite.config.ts`). Main build copies `.wasm` assets from `../opencode/dist/node` into `out/main/chunks/` and resolves `virtual:opencode-server` to that bundle (`electron.vite.config.ts`).

### Release channel

electron-builder / `predev` / `prebuild` channel mapping, product names, `appId`, and GitHub publish targets are canonical in [10.1 Install](10.1-install.md).

Runtime compile (`electron.vite.config.ts` IIFE) bakes `import.meta.env.OPENCODE_CHANNEL` used as `CHANNEL` (`src/main/constants.ts`): `dev` / `beta` / `prod` unchanged; env `"latest"` → `"prod"`; unset / other → `"dev"`.

Runtime main selects display name and `AppUserModelId` from compiled `CHANNEL` when packaged (`src/main/index.ts` `APP_NAMES`, `APP_IDS` matching the builder identities in [10.1 Install](10.1-install.md)). Unpackaged uses `app.setName("OpenCode Dev")` and `app.setAppUserModelId("ai.opencode.desktop.dev")`. Packaged `userData` is `join(app.getPath("appData"), appId)` unless `OPENCODE_TEST_ONBOARDING === "1"`.

### Runtime env

| Variable | When set / read | Effect |
|----------|-----------------|--------|
| `OPENCODE_CHANNEL` | Vite compile | Runtime `CHANNEL` (`src/main/constants.ts`). Builder/icon/publish mapping is [10.1 Install](10.1-install.md). |
| `OPENCODE_SIDECAR_V2` | Startup | `"1"` selects v2 background-CLI sidecar; otherwise v1 utility-process sidecar (`src/main/index.ts` `SIDECAR_VERSION`) |
| `OPENCODE_PORT` | v1 sidecar only | If parseable integer, binds local server to that port instead of ephemeral port |
| `OPENCODE_TEST_ONBOARDING` | Startup | `"1"` uses temp XDG paths, in-memory DB, skips migrate (`src/main/index.ts` `TEST_ONBOARDING`) |
| `OPENCODE_DISABLE_EMBEDDED_WEB_UI` | Set at startup | Main sets `"true"` before sidecar spawn (`src/main/index.ts`) |
| `NO_PROXY` / `no_proxy` | Startup | Loopback hosts appended if missing (`ensureLoopbackNoProxy` in `src/main/index.ts`, `src/main/sidecar.ts`) |
| `XDG_STATE_HOME` | Sidecar env | Defaults to app `userData` via `preferAppEnv` (`src/main/server.ts`) |

Sidecar spawn also sets `OPENCODE_EXPERIMENTAL_ICON_DISCOVERY=true`, `OPENCODE_EXPERIMENTAL_FILEWATCHER=true`, `OPENCODE_CLIENT=desktop` (`src/main/server.ts` `preferAppEnv`).

## Behavior

### Process architecture

| Process | Role | Isolation |
|---------|------|-----------|
| Main | App lifecycle, sidecar, IPC, menus, updater, WSL (Windows) | Node in Electron main |
| Preload | Exposes `window.api` via `contextBridge` | Must be sole renderer→main bridge (`packages/desktop/AGENTS.md`; `src/preload/index.ts`) |
| Renderer | Solid UI composing `@opencode-ai/app` providers and routes ([6.18 App](06.18-app.md) SoT for routes/exports) | `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` (`src/main/windows.ts` `createMainWindow`) |

IPC handlers are registered in `src/main/ipc.ts` (`packages/desktop/AGENTS.md`). Renderer code calls only `window.api` methods defined in `src/preload/types.ts` `ElectronAPI`.

### Startup and single instance

Import of `src/main/windows.ts` (from `src/main/index.ts`) runs `protocol.registerSchemesAsPrivileged` at module load so custom scheme `oc` is privileged **before** `app.whenReady` (`src/main/windows.ts`).

Then main:

1. Sets working directory to user home (macOS ripgrep workaround) and `OPENCODE_DISABLE_EMBEDDED_WEB_UI` (`src/main/index.ts`).
2. Configures app name, `AppUserModelId`, and `userData` at `join(app.getPath("appData"), appId)` — Windows `%APPDATA%/<appId>`, macOS `~/Library/Application Support/<appId>`, Linux XDG config (typically `~/.config/<appId>`); or a test temp root when `OPENCODE_TEST_ONBOARDING=1` (`src/main/index.ts`).
3. Calls `initializeOldLayoutEligibility` on that `userData` path, then logging and crash reporter — **before** the single-instance lock (`src/main/index.ts`).
4. Acquires a single-instance lock; a second instance quits immediately (`app.requestSingleInstanceLock`).
5. Awaits `app.whenReady()`, then `migrate()` (unless test onboarding) and `cleanupStoreFiles`.
6. Calls `app.setAsDefaultProtocolClient("opencode")` and `registerRendererProtocol()`, then dock icon, auto-updater setup, and IPC registration (`src/main/index.ts`).
7. Forks a **loading task** (`Effect.forkChild`) that brings up the local backend, fulfills `serverReady` with `{ url, username, password }`, and—for v1—awaits sidecar health for up to 30 seconds before finishing.
8. **Awaits** that loading fiber (`Fiber.await`) so window restore does not run until the task completes (including the v1 health wait).
9. Restores persisted browser windows (or creates one) and application menu (`restoreMainWindows`).

Renderer IPC `await-initialization` can unblock once step 7 succeeds `serverReady`, but main-process window creation waits on step 8 (`src/main/index.ts`).

Second-instance argv entries starting with `opencode://` are forwarded as deep links to the focused window (`src/main/index.ts` `second-instance`; macOS `open-url`).

### Local backend sidecar

Two modes, selected by `OPENCODE_SIDECAR_V2`:

| Mode | Mechanism | Credentials returned |
|------|-----------|------------------------|
| **v1** (default) | `utilityProcess.fork` of bundled `sidecar.js`, which dynamic-imports `virtual:opencode-server` and calls `Server.listen` on loopback | `username: "opencode"`, random UUID `password`, URL `http://127.0.0.1:<port>` |
| **v2** | `startBackgroundCli` runs bundled/staged `opencode-cli` (`service start`, `service get password`) | `username: "opencode"`, CLI-reported password, service URL |

v1 port selection: `OPENCODE_PORT` if valid, else ephemeral port on `127.0.0.1` (`src/main/index.ts`). v1 sidecar CORS allows origin `oc://renderer` (`src/main/sidecar.ts`). Renderer awaits backend via IPC `await-initialization`, which blocks on the shared `serverReady` deferred (`src/main/index.ts`, `src/preload/index.ts`).

Health checks poll `/api/health` and `/global/health` with Basic auth when a password is set (`src/main/server.ts` `checkHealth`). v1 startup waits up to 30 seconds on sidecar health after fork (`src/main/index.ts`).

On quit or relaunch, main stops the v1 listener and all WSL sidecars (`killSidecar`, `wslServers.stopAll`).

### Renderer integration

The renderer entry (`src/renderer/index.tsx`) mounts a desktop `PlatformProvider` with `platform: "desktop"`, wires:

- **Server connection** — `awaitInitialization` + optional default remote URL from store (`getDefaultServerUrl` / `setDefaultServerUrl`, key `defaultServerUrl` in `src/main/store-keys.ts`).
- **Persistence** — namespaced key-value stores and draft blob store via IPC (`store-*`, `draft-*` handlers in `src/main/ipc.ts`; SQLite drafts at `<userData>/drafts.sqlite`).
- **Deep links** — initial and live `opencode://` URLs surfaced as `window.__OPENCODE__.deepLinks` and custom event `opencode:deep-link`.
- **Updater state** — subscribes to main-process `updater-state` events. `UpdaterState` type is [6.18 App](06.18-app.md) export `./updater`.
- **WSL servers** — exposed only when renderer detects Windows (`src/renderer/index.tsx` `wslServersApi`). WSL types are [6.18 App](06.18-app.md) export `./wsl/types`.
- **Native menus** — renderer sends typed native translation bundles; main rebuilds menus via `nativeT(...)` (`src/main/ipc.ts` `set-native-translations`; `packages/desktop/AGENTS.md` i18n rules). Menu tree `DESKTOP_MENU` is [6.18 App](06.18-app.md) export `./desktop-menu` (`packages/desktop/src/main/menu.ts`). Desktop-native locale labels are [6.18 App](06.18-app.md) export `./i18n/desktop-native`.

First-launch onboarding is gated by store flag `firstLaunchOnboardingComplete`; completion may create `Documents/Default Project` (`src/main/onboarding.ts`). Existing installs before layout migration set `oldLayoutEligible` once from prior app state via `hasExistingAppState` on `userData` entries (`src/main/onboarding.ts` `initializeOldLayoutEligibility`; `src/main/install-state.ts`).

Window geometry and multi-window IDs persist via `electron-window-state` files and `windowIds` store key (`src/main/windows.ts`, `src/main/window-registry.ts`). Default window size 1280×800.

### AppInterface mount

Canonical desktop host of `AppInterface` (`packages/desktop/src/renderer/index.tsx`): under `PlatformProvider` `platform: "desktop"` and `AppBaseProviders`, mounts `AppInterface` with sidecar/WSL `servers`, `startup` onboarding, and **no** `disableHealthCheck`. Preload exposes `window.api` (`src/preload/index.ts`). App routes, `AppInterface` props, and `AppBaseProviders` remain [6.18 App](06.18-app.md).

### WSL servers

On Windows, after sidecar ready, main initializes a WSL servers controller that can spawn per-distro sidecars, persist configs under `wslServers` store key, and expose IPC under `wsl-servers-*` (`src/main/wsl/servers.ts`, `src/main/wsl/ipc.ts`, `src/main/index.ts`). Renderer WSL connection helpers filter ready servers (`src/renderer/wsl/connections.ts`).

### Auto-update

When `UPDATER_ENABLED`, `electron-updater` uses channel `latest`, manual download/install (no auto-download on check), downgrade allowed (`src/main/updater.ts`). Periodic check every 10 minutes (`src/main/index.ts`). Install calls `quitAndInstall` after `setAppQuitting()` so window IDs persist (`src/main/updater.ts`).

### Native UX constraints

User-visible strings in main-process menus, dialogs, and pickers must use i18n keys via `nativeT(...)`; renderer uses its typed i18n layer (`packages/desktop/AGENTS.md`). Hardcoded English in production native UI is forbidden by project notes (descriptive of repo policy in `AGENTS.md`, not a runtime enforceable). Native locale catalog export is [6.18 App](06.18-app.md) `./i18n/desktop-native`.

## Error handling

| Situation | Behavior |
|-----------|----------|
| Second instance without lock | Main process exits immediately (`app.quit` after failed `requestSingleInstanceLock`) |
| v1 sidecar not ready within 60s | Spawn rejects with stall timeout error (`src/main/server.ts` `SIDECAR_START_STALL_TIMEOUT`) |
| v1 sidecar exits before ready | Spawn rejects; utility process killed if still running (`src/main/server.ts`) |
| v1 health wait (30s) | Logged error; startup continues (`src/main/index.ts` loading task) |
| Loading task failure | `forwardInitializationFailure` completes `serverReady` deferred with failure; renderer `initializationData` throws any initialization error with `localServerStartup: true` via `markLocalServerStartup`; when the message starts with Electron's `await-initialization` IPC wrapper prefix, that prefix is stripped first (`src/renderer/initialization.ts`; tests in `src/main/index.test.ts`, `src/renderer/initialization.test.ts`) |
| Sidecar stop | Posts `stop` message; kills after 6s if still running (`SIDECAR_STOP_TIMEOUT` in `src/main/server.ts`) |
| Invalid native translation IPC | Throws `Invalid native translation sender` or `Invalid native translation bundle` (`src/main/ipc.ts`) |
| Proxy / TLS setup failures | Warn-only logs; app continues (`useEnvProxy`, certificate merge in `src/main/index.ts`) |
| Store cleanup failure | Warn-only (`src/main/index.ts`) |
| Updater install failure | Clears quitting flag so window lifecycle resumes (`src/main/updater.ts`) |
| WSL init failure | Logged error; non-fatal (`src/main/index.ts`) |

Non-macOS platforms quit when all windows closed; macOS stays running until explicit quit (`window-all-closed` handler in `src/main/index.ts`).
