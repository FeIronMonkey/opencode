# 6.10 LLM

> **Spec chapter:** Schema-first LLM core: one request/event/tool language, provider routes, and one-turn generate/stream.
> **Parent:** [6 Components](../06-components.md)
> **Index:** [README.md](../README.md)

**File:** `packages/llm/` (`@opencode-ai/llm`, private workspace package)

Retrospective description of shipped `@opencode-ai/llm` behavior (C8). The package is an Effect Schema-first LLM core: Schema classes under `src/schema/` are the canonical runtime data model; `LLM.request` and related helpers construct those classes (`packages/llm/AGENTS.md`; `packages/llm/src/llm.ts`). Runtime dependencies are `effect`, `@opencode-ai/schema`, `aws4fetch`, `@smithy/eventstream-codec`, and `@smithy/util-utf8` (`packages/llm/package.json`). Canonical definitions of re-exported schema types such as `ProviderMetadata` and `ToolContent` belong in [8 Domain model](08-domain-model.md) (OQ-6.10-1).

The package does not own session, permission, plugin, or telemetry concerns (`packages/llm/AGENTS.md`). Host consumption lives in [6.1 Agent CLI](06.1-agent-cli.md) and [6.2 Core](06.2-core.md) (OQ-6.10-2).

### Request construction

`LLM.request(input)` returns `LLMRequest`. Ergonomic fields normalize as follows (`packages/llm/src/llm.ts` `request`, `RequestInput`):

| Input | Canonical field |
|-------|-----------------|
| `system?: string \| SystemPart \| ReadonlyArray<SystemPart>` | `SystemPart.content(...)` → `system` array |
| `prompt?: string \| ContentPart \| ReadonlyArray<ContentPart>` | appended as `Message.user(prompt)` after `messages` |
| `messages?` | each entry `Message.make` |
| `tools?` | each entry `ToolDefinition.make`; omitted → `[]` |
| `toolChoice?` | `ToolChoice.make` when present |
| `generation?` | `GenerationOptions.make` when present |
| `http?` | `HttpOptions.make` when present |

`LLM.updateRequest(request, patch)` rebuilds via `request({ ...requestInput(input), ...patch })` (`packages/llm/src/llm.ts` `updateRequest`). `LLMRequest.update` is the Schema-class patcher (`packages/llm/src/schema/messages.ts` `LLMRequest.update`).

`LLMRequest` fields (`packages/llm/src/schema/messages.ts` `LLMRequest`): `id?`, `model`, `system`, `messages`, `tools`, `toolChoice?`, `generation?`, `providerOptions?`, `http?`, `responseFormat?`, `cache?`, `metadata?`.

`Message` constructors (`packages/llm/src/schema/messages.ts` `Message`): `user`, `assistant`, `system` (chronological text-only operator update, distinct from `LLMRequest.system`), `tool`. Content part types: `text`, `media`, `tool-call`, `tool-result`, `reasoning` (`ContentPart` tagged union).

`ToolChoice.make` (`packages/llm/src/schema/messages.ts` `ToolChoice`):

| Input | Result |
|-------|--------|
| `"auto"` / `"none"` / `"required"` | `{ type }` of that mode |
| other string | `{ type: "tool", name }` via `named` |
| `ToolDefinition` | `named(definition.name)` |
| object / existing `ToolChoice` | as given |

`GenerationOptions` fields: `maxTokens`, `temperature`, `topP`, `topK`, `frequencyPenalty`, `presencePenalty`, `seed`, `stop` (`packages/llm/src/schema/options.ts` `GenerationOptions`). Merge uses last-defined wins per field (`mergeGenerationOptions`). `HttpOptions` merges nested `body` records and string `headers`/`query` (`mergeHttpOptions`). `ProviderOptions` merge per provider key (`mergeProviderOptions`).

`Model.make` brands `id` as `LLM.ModelID` and `provider` as `LLM.ProviderID` and stores `route`, optional `defaults`, optional `compatibility` (`packages/llm/src/schema/options.ts` `Model`). `ModelCompatibility.toolSchema` literals: `"gemini"`, `"moonshot"` (`ModelToolSchemaCompatibility`).

### Route composition

`Route.make` composes protocol, endpoint, auth, and either explicit `transport` or `HttpTransport.httpJson({ framing })` (`packages/llm/src/route/client.ts` `make`, `MakeInput`). Default auth is `Auth.none` when omitted (`makeFromTransport`).

`Route.model` throws `Error` (not `LLMError`) when the route has no provider: `` `Route.model(${route.id}) requires a provider` ``, or when the endpoint has no string `baseURL`: `` `Route.model(${route.id}) requires an endpoint baseURL — configure it on the route first` `` (`packages/llm/src/route/client.ts` `makeRouteModel`).

`LLMClient.Service` is Context tag `"@opencode/LLMClient"`. `LLMClient.layer` requires `RequestExecutor.Service` and optionally `WebSocketExecutor.Service` (`packages/llm/src/route/client.ts` `Service`, `layer`). `RequestExecutor.layer` requires `HttpClient.HttpClient`; `RequestExecutor.fetchLayer` provides fetch (`packages/llm/src/route/executor.ts` `layer`, `fetchLayer`).

`Endpoint.path(value, options?)` stores `baseURL?`, `path`, `query?` (`packages/llm/src/route/endpoint.ts` `path`). `Framing.sse` has `id: "sse"` (`packages/llm/src/route/framing.ts`). HTTP JSON transport `id` is `"http-json"`; SSE variant `"http-json/sse"` (`packages/llm/src/route/transport/http.ts`). WebSocket JSON transport `id` is `"websocket-json"` (`packages/llm/src/route/transport/websocket.ts`). Bedrock framing `id` is `"aws-event-stream"` (`packages/llm/src/protocols/bedrock-event-stream.ts`).

## Behavior

### Compile, prepare, stream, generate

Compile (`packages/llm/src/route/client.ts` `compile`) applies cache policy after merging options, then `route.body.from` + schema validate, then `prepareTransport`. Option merge order for generation / providerOptions / http: route defaults, then model defaults, then request (`resolveRequestOptions`; `packages/llm/test/prepare.test.ts` `"prepares bodies with route defaults, model defaults, and call options in order"`).

| Method | Behavior |
|--------|----------|
| `LLMClient.prepare(request)` | Compile without sending. `PreparedRequest` `id` is `request.id ?? "request"`; `metadata.transport` is `route.transport.id` (`prepareWith`). Generic `prepare<Body>` is a type-level assertion only (`PreparedRequestOf` comment). |
| `LLMClient.stream(request)` | Requires `LLMClient.Service`. Frames → decode `protocol.stream.event` → `mapAccumEffect` `step`; optional `terminal` `takeUntil`; optional `onHalt`. Decode failure: `` `Invalid ${route} stream event` `` with `route` `${provider}/${route.id}` (`decodeEvent`, `streamError`). |
| `LLMClient.generate(request)` | Folds the stream with `LLMResponse.empty` / `LLMResponse.reduce` / `LLMResponse.complete`. If no terminal finish: `InvalidProviderOutput` `` `Provider stream ended without a terminal finish event` `` (`generateWith`). |
| `LLM.generate` / `LLM.stream` | Re-exports of `LLMClient.generate` / `stream` (`packages/llm/src/llm.ts`). |

`stream` and `generate` each run one provider turn; they do not loop tools (`packages/llm/AGENTS.md`; `packages/llm/test/tool-runtime.test.ts` `"executes tool calls for one step without looping by default"`).

### LLMEvent stream

Event `type` tags (`packages/llm/src/schema/events.ts`): `step-start`, `text-start`, `text-delta`, `text-end`, `reasoning-start`, `reasoning-delta`, `reasoning-end`, `tool-input-start`, `tool-input-delta`, `tool-input-end`, `tool-call`, `tool-result`, `tool-error`, `step-finish`, `finish`, `provider-error`. Guards: `LLMEvent.is.*` camelCase aliases of `LLMEvent.guards["kebab-case"]`.

`FinishReason` literals: `"stop"`, `"length"`, `"tool-calls"`, `"content-filter"`, `"error"`, `"unknown"` (`packages/llm/src/schema/ids.ts`). `ReasoningEffort` literals: `"none"`, `"minimal"`, `"low"`, `"medium"`, `"high"`, `"xhigh"`, `"max"`. `TextVerbosity`: `"low"`, `"medium"`, `"high"`.

`Usage` stores inclusive `inputTokens` / `outputTokens` / `totalTokens` plus non-overlapping `nonCachedInputTokens`, `cacheReadInputTokens`, `cacheWriteInputTokens`, `reasoningTokens` (`packages/llm/src/schema/events.ts` `Usage`). `visibleOutputTokens` is `Math.max(0, (outputTokens ?? 0) - (reasoningTokens ?? 0))`. Shared token helpers: `totalTokens`, `subtractTokens` (`Math.max(0, …)`), `sumTokens` (`packages/llm/src/protocols/shared.ts`). Anthropic-style inclusive `inputTokens` is summed from the breakdown; Anthropic does not split thinking out of `output_tokens`, so `reasoningTokens` stays undefined there (`Usage` docstring).

### LLMResponse assembly

`LLMResponse` fields: `message`, `events`, `usage?`, `finishReason` (`packages/llm/src/schema/events.ts` `LLMResponse`). Accessors: `text` (joined `text-delta`), `reasoning` (joined `reasoning-delta`), `toolCalls` (`is.toolCall`). `complete` returns `undefined` until `finishReason` is set (from `finish` or `provider-error` defaulting reason `"error"`). Tool-call content is assembled only after a completed `tool-call` event (`packages/llm/test/response.test.ts` `"assembles tool-call content only after the completed tool call event"`).

### Cache policy

`applyCachePolicy` runs at compile (`packages/llm/src/cache-policy.ts`; `packages/llm/src/route/client.ts` `compile`).

| `request.cache` | Resolved object |
|-----------------|-----------------|
| `undefined` or `"auto"` | `{ tools: true, system: true, messages: "latest-user-message" }` (`AUTO`) |
| `"none"` | `{}` (`NONE`) — no auto placement; existing part `CacheHint`s still flow |
| object | used as-is (`tools?`, `system?`, `messages?`, `ttlSeconds?`) |

`messages` strategies: `"latest-user-message"`, `"latest-assistant"`, `{ tail: number }` (last N messages). Auto placement skips a boundary that already has `cache`. Hint type is `"ephemeral"`; `ttlSeconds` copied when set (`makeHint`).

Inline-hint injection runs only when `request.model.route.id` is in `RESPECTS_INLINE_HINTS`: `"anthropic-messages"`, `"bedrock-converse"`. Other routes (including OpenAI Chat and Gemini) return the request unchanged (`packages/llm/src/cache-policy.ts`; `packages/llm/test/cache-policy.test.ts` `"'auto' is a no-op on OpenAI (implicit caching protocol)"`, `"'auto' is a no-op on Gemini (out-of-band caching protocol)"`).

Anthropic/Bedrock wire TTL: `ttlSeconds >= 3600` → `"1h"`, otherwise provider default 5m (`packages/llm/src/protocols/utils/cache.ts` `ttlBucket`). Both protocols cap cache breakpoints at 4, allocated tools → system → messages; excess drops with `Effect.logWarning` messages `` `Anthropic Messages: dropped ${n} cache breakpoint(s); the API allows at most 4 per request.` `` and `` `Bedrock Converse: dropped ${n} cache breakpoint(s); the API allows at most 4 per request.` `` (`ANTHROPIC_BREAKPOINT_CAP`, `BEDROCK_BREAKPOINT_CAP`).

### Chronological system updates

`Message.system` is a chronological privileged update, not the initial `LLMRequest.system` (`packages/llm/src/schema/messages.ts` `Message.system`; `packages/llm/test/llm.test.ts` `"builds chronological text-only system updates separately from the initial system prompt"`). Content must be text; `systemUpdateText` rejects other part types via `unsupportedContent` (`packages/llm/src/protocols/shared.ts`).

Native chronological system lowering: Anthropic Messages only when `String(request.model.id) === "claude-opus-4-8"` (`packages/llm/src/protocols/anthropic-messages.ts` `supportsNativeSystemUpdates`). All other routes/models lower via `wrapSystemUpdate`: `` `<system-update>\n${escapeSystemUpdateText(joinText(parts))}\n</system-update>` `` with `&`, `<`, `>` escaped to `&amp;`, `&lt;`, `&gt;` (`packages/llm/src/protocols/shared.ts` `wrapSystemUpdate`, `escapeSystemUpdateText`).

### Tools and ToolRuntime.dispatch

`Tool.make` has typed (`parameters` + `success` Schemas) and dynamic (`jsonSchema`, optional `outputSchema`) modes (`packages/llm/src/tool.ts` `make`). `toDefinitions(tools)` yields `ToolDefinition` array with names from record keys (`toDefinitions`). `execute` is optional so schemas can be exposed without local handlers (`packages/llm/test/tool-runtime.test.ts` `"can expose tool schemas without executing tool calls"`).

`ToolRuntime.dispatch(tools, call)` (`packages/llm/src/tool-runtime.ts` `dispatch`):

| Condition | Result events |
|-----------|----------------|
| Unknown name | `tool-error` + `tool-result` `type: "error"` value `` `Unknown tool: ${call.name}` `` |
| No `execute` | value `` `Tool has no execute handler: ${call.name}` `` |
| Parameters decode fail | `ToolFailure` message `` `Invalid tool input: ${error.message}` `` → same error events |
| Handler `ToolFailure` | `tool-error` message `failure.message` plus `tool-result` error |
| Success encode fail | `` `Tool returned an invalid value for its success schema: ${error.message}` `` |
| Success | `tool-result` with encoded result / optional `output` |

Anything that is not `ToolFailure` from a handler is a defect and fails the Effect (`packages/llm/src/schema/errors.ts` `ToolFailure` comment). Provider-executed calls (`providerExecuted: true`) are not locally dispatched (`packages/llm/test/tool-runtime.test.ts` `"does not dispatch provider-executed tool calls"`).

Streamed tool-call JSON parse uses `parseToolInput`; empty input is `"{}"`; error message `` `Invalid JSON input for ${route} tool call ${name}` `` (`packages/llm/src/protocols/shared.ts` `parseToolInput`).

Anthropic hosted tool names lowered as `web_search`, `code_execution`, `web_fetch` with matching `*_tool_result` blocks (`packages/llm/src/protocols/anthropic-messages.ts`). OpenAI Responses hosted items include `web_search_call`, `web_search_preview_call`, `file_search_call`, `code_interpreter_call`, `computer_use_call`, `image_generation_call`, `mcp_call`, `local_shell_call` (`packages/llm/src/protocols/openai-responses.ts`).

Tool-schema projection: `moonshot` and `gemini` compatibility (`packages/llm/test/tool-schema-projection.test.ts`).

### generateObject

`LLM.generateObject` forces tool name `generate_object` with description `"Return the structured result by calling this tool."` and `ToolChoice.named("generate_object")` (`packages/llm/src/llm.ts` `GENERATE_OBJECT_TOOL_NAME`, `runGenerateObject`). Typed mode passes Effect `schema` as tool `parameters`; dynamic mode uses `jsonSchema`. Missing forced call:

`InvalidProviderOutput` message `` `generateObject: model did not call the forced \`generate_object\` tool` `` (`module: "LLM"`, `method: "generateObject"`).

Decode failure: `` `generateObject: tool input failed schema decode: ${error.message}` ``.

## Error handling

`LLMError` tagged `"LLM.Error"` with `module`, `method`, `reason` (`packages/llm/src/schema/errors.ts`). `message` is `` `${this.module}.${this.method}: ${this.reason.message}` ``. `retryable` / `retryAfterMs` delegate to `reason`.

| `reason._tag` | `retryable` | Notes |
|---------------|-------------|-------|
| `InvalidRequest` | `false` | optional `classification: "context-overflow"` |
| `NoRoute` | `false` | message `` `No LLM route for ${provider}/${model} using ${route}` `` (schema class; no constructor call site in this package) |
| `Authentication` | `false` | `kind`: `"missing"`, `"invalid"`, `"expired"`, `"insufficient-permissions"`, `"unknown"` |
| `RateLimit` | `true` | optional `retryAfterMs` |
| `QuotaExceeded` | `false` | |
| `ContentPolicy` | `false` | |
| `ProviderInternal` | `true` | includes `status` |
| `Transport` | `false` | timeout `kind: "Timeout"`; generic `"HTTP transport failed"` |
| `InvalidProviderOutput` | `false` | |
| `UnknownProvider` | `false` | |

HTTP status mapping (`packages/llm/src/route/executor.ts` `statusReason`): body matching `/content[-_\s]?policy|content_filter|safety/i` → `ContentPolicy`; `401` → Authentication `invalid`; `403` → `insufficient-permissions`; `429` with `/insufficient[-_\s]?quota|quota[-_\s]?exceeded/i` → `QuotaExceeded`, else `RateLimit`; `400`/`404`/`409`/`413`/`422` → `InvalidRequest` with `context-overflow` when `isContextOverflow(body)`; `>= 500` or retryable status → `ProviderInternal`; else `UnknownProvider`. Provider message: `` `Provider request failed with HTTP ${status}: ${body}` `` when body length `<= 500`, else `` `Provider request failed with HTTP ${status}` `` (`providerMessage`).

Retryable HTTP statuses: `429`, `503`, `504`, `529` (`retryableStatus`). `MAX_RETRIES = 2`, `BASE_DELAY_MS = 500`, `MAX_DELAY_MS = 10_000`. Delay uses `retryAfterMs` capped at `MAX_DELAY_MS`, else jittered `BASE_DELAY_MS * 2 ** attempt * [0.8, 1.2]` (`retryDelay`, `retryStatusFailures`). `Retry-After` parsed as millis header, seconds, or HTTP date (`retryAfterMs`). Rate-limit headers: `x-ratelimit-limit|remaining|reset-*` and `anthropic-ratelimit-*-limit|remaining|reset` (`rateLimitDetails`). Request id from `x-request-id`, `request-id`, `x-amzn-requestid`, `x-amz-request-id`, `x-goog-request-id`, `cf-ray` (`requestId`).

`isContextOverflow(message)` matches listed token/context patterns and `/^4(00|13)\s*(status code)?\s*\(no body\)/i`, excluding `/^(throttling error|service unavailable):/i`, `/rate limit/i`, `/too many requests/i` (`packages/llm/src/provider-error.ts`). `isContextOverflowFailure` is true for `LLMError` `InvalidRequest` with that classification, or `provider-error` events with `classification === "context-overflow"`.
