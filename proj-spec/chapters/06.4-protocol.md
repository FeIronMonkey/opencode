# 6.4 Protocol

> **Spec chapter:** Shipped Effect `HttpApi` contract for instance routes (`@opencode-ai/protocol`).
> **Parent:** [6 Components](../06-components.md)
> **Index:** [README.md](../README.md)

**File:** `packages/protocol/` (package `@opencode-ai/protocol`)

This chapter is a **retrospective** description of shipped Protocol sources (C8). `@opencode-ai/protocol` is the assigned home for this package (`tmp/executive/opencode-retrospective-spec/findings/T1-chapter-map.md` package assignment). It defines the public `HttpApi` groups, shared error schemas, and middleware *slots*. Concrete HTTP hosting and handler implementations belong to [6.5 Server](06.5-server.md). Domain types come from [8 Domain model](08-domain-model.md). Client generation from this contract belongs to [6.7 Client](06.7-client.md).

`protocol` is one name on the multi-leaf packages consistency token; that token’s full list is `schema`, `core`, `protocol`, `server`, `client`, `sdk`, `sdk-next`, `plugin`, `ui` (`tmp/executive/opencode-retrospective-spec/findings/T1-chapter-map.md` consistency tokens; T1 numbering also assigns those packages to other leaves). This chapter does not treat `packages/protocol` as that whole list.

After changing the public Protocol or Server `HttpApi`, the workspace rule is to run `bun run generate` from `packages/client` and not to edit `src/generated` or `src/generated-effect` directly (`AGENTS.md`).

### Package identity and exports

The package is private workspace protocol (`packages/protocol/package.json`). Callers import TypeScript modules under `src/` via `@opencode-ai/protocol/<path>` matching `src/<path>.ts`.

### Runtime dependencies

Declared runtime dependencies are `@opencode-ai/schema` and `effect` (`packages/protocol/package.json`). Workspace dependency direction (quote): Schema to Core and Protocol, then from Core and Protocol to Server. Client runtime code may depend on Schema and Protocol but never Core or Server; `sdk-next` composes Client, Core, and Server (`AGENTS.md`). T1 restates the same dep direction token (`tmp/executive/opencode-retrospective-spec/findings/T1-chapter-map.md` consistency tokens). T1 related edges for this leaf: 6.4 depends 8 → consumed: 6.1, 6.5, 6.7.

### HttpApi factories

`makeApiFromGroup` builds one `HttpApi` named `"server"`, adds groups in a fixed order, then attaches API-wide middleware (`packages/protocol/src/api.ts` `makeApiFromGroup`).

`makeApi` uses `makeEventGroup(options.definitions)` for the event group. `makeDefaultApi` uses the prebuilt `EventGroup` (`makeApi`, `makeDefaultApi`).

Comment at `makeApiFromGroup`: Protocol owns middleware placement, while Server injects concrete keys so Core service identities stay downstream.

### Shared location query

`LocationQuery` is a struct with optional `location` object `{ directory?: string, workspace?: string }` (`LocationQuery`, `packages/protocol/src/groups/location.ts`). `locationQueryOpenApi` sets OpenAPI `style: "deepObject"` and `explode: true` on the query parameter named `location` (`locationQueryOpenApi`).

`Location.response(...)` wraps success payloads; the wrapper schema is defined in schema (`Location` import from `@opencode-ai/schema/location`). Shape details are [8 Domain model](08-domain-model.md).

## Behavior

Protocol declares routes, codecs, declared errors, and OpenAPI identifiers. It does not implement request handlers.

### HttpApi group assembly

`makeApiFromGroup` adds groups in this order (`packages/protocol/src/api.ts`):

| Group constructor | HttpApi group id | Location middleware at assembly |
|-------------------|------------------|---------------------------------|
| `HealthGroup` | `server.health` | none |
| `LocationGroup` | `server.location` | `locationMiddleware` |
| `AgentGroup` | `server.agent` | `locationMiddleware` |
| `makeSessionGroup(sessionLocationMiddleware)` | `server.session` | per-endpoint `sessionLocationMiddleware` inside the group |
| `MessageGroup` | `server.message` | `sessionLocationMiddleware` on the group |
| `ModelGroup` | `server.model` | `locationMiddleware` |
| `ProviderGroup` | `server.provider` | `locationMiddleware` |
| `IntegrationGroup` | `server.integration` | `locationMiddleware` |
| `CredentialGroup` | `server.credential` | `locationMiddleware` |
| `makePermissionGroup(locationMiddleware, sessionLocationMiddleware)` | `server.permission` | see [Permissions](#permissions) |
| `FileSystemGroup` | `server.fs` | `locationMiddleware` |
| `CommandGroup` | `server.command` | `locationMiddleware` |
| `SkillGroup` | `server.skill` | `locationMiddleware` |
| `eventGroup` argument | `server.event` | none in `makeApiFromGroup` |
| `PtyGroup` | `server.pty` | `locationMiddleware` |
| `makeQuestionGroup(locationMiddleware, sessionLocationMiddleware)` | `server.question` | see [Questions](#questions) |
| `ReferenceGroup` | `server.reference` | `locationMiddleware` |
| `ProjectCopyGroup` | `server.projectCopy` | `locationMiddleware` |

After groups, the API applies `Authorization` then `SchemaErrorMiddleware` (`makeApiFromGroup`).

### API-wide middleware slots

`Authorization` is `HttpApiMiddleware.Service` id `"@opencode/HttpApiAuthorization"` with error `UnauthorizedError` (`Authorization`, `packages/protocol/src/middleware/authorization.ts`).

`SchemaErrorMiddleware` is `HttpApiMiddleware.Service` id `"@opencode/HttpApiSchemaError"` with error `InvalidRequestError` (`SchemaErrorMiddleware`, `packages/protocol/src/middleware/schema-error.ts`).

### Session list cursor and history query

`SessionsCursor` is a branded string. `SessionsCursor.make` JSON-encodes a union of directory / project / all list fields with `limit` omitted and `anchor: Session.ListAnchor`, then Base64URL-encodes that JSON (`SessionsCursor`, `encodeSessionsCursor`, `Encoding.encodeBase64Url`). `SessionsCursor.parse` Base64URL-decodes then JSON-decodes; both Base64URL failure and JSON/schema failure become the string `"Invalid cursor"` (`invalidCursor`, `SessionsCursor.parse`).

`SessionHistoryQuery`: optional `limit` (`NumberFromString` → `PositiveInt` checked `isLessThanOrEqualTo(100)`), optional `after` (`NumberFromString` → `NonNegativeInt`) (`SessionHistoryQuery`, `SessionHistoryLimit`).

### Events

`makeEventGroup(definitions)` builds `server.event` with GET `/api/event` named `event.subscribe`, SSE success of a union of the supplied `Definition` schemas plus a synthetic `{ type: "server.connected", data: {} }` variant when no definition has `type === "server.connected"` (`schema`, `make`, `packages/protocol/src/groups/event.ts`). OpenAPI identifier `v2.event.subscribe`.

`EventGroup` / `OpenCodeEvent` use `EventManifest.ServerDefinitions` (`event` const). Event payload fields shared by the synthetic connected event: `id`, optional `metadata`, optional `durable` `{ aggregateID, seq, version }`, optional `location` (`fields`).

### PTY

Constants (`packages/protocol/src/groups/pty.ts`): `PTY_CONNECT_TICKET_QUERY` is `"ticket"`; `PTY_CONNECT_TOKEN_HEADER` is `"x-opencode-ticket"`; `PTY_CONNECT_TOKEN_HEADER_VALUE` is `"1"`. Path regex `PTY_CONNECT_PATH` is `/^\/api\/pty\/[^/]+\/connect$/`.

`hasPtyConnectTicketURL(url)` returns whether `url.pathname` matches `PTY_CONNECT_PATH` and `url.searchParams.get("ticket")` is truthy.
