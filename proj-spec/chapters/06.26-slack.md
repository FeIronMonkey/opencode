# 6.26 Slack

> **Spec chapter:** Slack Socket Mode bot that maps channel threads to OpenCode sessions via `@opencode-ai/sdk`.
> **Parent:** [6 Components](../06-components.md)
> **Index:** [README.md](../README.md)

**File:** `packages/slack/src/index.ts` (`@opencode-ai/slack`)

This slice is the Slack bot package: a Bolt app in Socket Mode that starts a local OpenCode process with `createOpencode`, keeps one session per Slack channel+thread, prompts that session with incoming message text, posts the prompt result back into the thread, and posts completed tool parts as they arrive. This pass is retrospective of shipped code.

`packages/slack/sst-env.d.ts` is an SST-generated stub (`/* This file is auto-generated by SST. Do not edit. */`). It is not the behavioral source of truth. Runtime configuration is `process.env` in `packages/slack/src/index.ts`.

OpenCode client/server behavior of `createOpencode` is specified in [6.8 Legacy JS SDK](06.8-sdk.md). This chapter only records the calls this package makes.

## Behavior

### Process start

On load, `packages/slack/src/index.ts`:

1. Constructs the Bolt `App` as in Construction.
2. Logs bot configuration presence flags.
3. Awaits `createOpencode({ port: 0 })` from `@opencode-ai/sdk`.
4. Starts an async loop on `opencode.client.event.subscribe()` (see Tool completion posts).
5. Registers `app.use` middleware that `JSON.stringify`s `context` at log prefix `📡 Raw Slack event:` then `await next()`.
6. Registers `app.message` and `app.command("/test")`.
7. `await app.start()`, then logs `⚡️ Slack bot is running!`.

README: after `bun dev`, the bot responds to messages in channels where it is added and creates separate OpenCode sessions per thread (`packages/slack/README.md` Usage).

### Session map

In-memory `sessions` is `Map<string, { client; server; sessionId; channel; thread }>`. The map key is `` `${channel}-${thread}` `` (`packages/slack/src/index.ts`).

`thread` for a Slack message is `(message as any).thread_ts || message.ts`. Channel-root messages therefore key by `channel` plus that message `ts`.

### Incoming messages

`app.message` (`packages/slack/src/index.ts`):

| Condition | Effect |
|----------|--------|
| `message.subtype` is truthy, or `"text"` is not in `message`, or `message.text` is falsy | Log skip (`⏭️ Skipping message - no text or has subtype`); return |
| Otherwise | Process `message.text` |

When processing:

1. Resolve `channel`, `thread`, `sessionKey`.
2. If no map entry: `opencode.client.session.create({ body: { title: \`Slack thread ${thread}\` } })`. On `createResult.error`, see Error handling. On success, store `{ client: opencode.client, server: opencode.server, sessionId: createResult.data.id, channel, thread }` and call `client.session.share({ path: { id: createResult.data.id } })`. When `!shareResult.error && shareResult.data`, `chat.postMessage` to `{ channel, thread_ts: thread, text: shareResult.data.share?.url }`.
3. `session.client.session.prompt({ path: { id: session.sessionId }, body: { parts: [{ type: "text", text: message.text }] } })`.
4. On `result.error`, see Error handling.
5. Reply text is `result.data.info?.content`, else `result.data.parts` filtered to `p.type === "text"` mapped to `p.text` joined with `"\n"`, else `"I received your message but didn't have a response."`
6. `say({ text: responseText, thread_ts: thread })`.

Existing map entries skip create/share and go to prompt.

### Tool completion posts

The subscribe loop (`packages/slack/src/index.ts`): for each `event` on `events.stream`, if `event.type === "message.part.updated"` and `event.properties.part.type === "tool"`, iterate `sessions` and call `handleToolUpdate` for the first entry whose `sessionId === part.sessionID`.

`handleToolUpdate(part, channel, thread)`: if `part.state.status !== "completed"`, return. Otherwise `app.client.chat.postMessage({ channel, thread_ts: thread, text: \`*${part.tool}* - ${part.state.title}\` })`. Failures are swallowed (`.catch(() => {})`).

### Slash command `/test`

`app.command("/test")` (`packages/slack/src/index.ts`): `await ack()`, then `say("🤖 Bot is working! I can hear you loud and clear.")`.

## Error handling

| Condition | Result | Source |
|-----------|--------|--------|
| `client.session.create` returns `error` | Log `❌ Failed to create session:`; `say({ text: "Sorry, I had trouble creating a session. Please try again.", thread_ts: thread })`; return (no map entry) | `app.message` (`packages/slack/src/index.ts`) |
| `client.session.share` has `error` or falsy `data` | No share URL post; session remains in the map; prompt still runs | `app.message` |
| `session.client.session.prompt` returns `error` | Log `❌ Failed to send message:`; `say({ text: "Sorry, I had trouble processing your message. Please try again.", thread_ts: thread })`; return | `app.message` |
| `chat.postMessage` for a completed tool part rejects | Ignored | `handleToolUpdate` `.catch(() => {})` |

Bolt `App` construction does not substitute fallbacks when env vars are missing; they are passed through as `process.env` values (`packages/slack/src/index.ts`).
