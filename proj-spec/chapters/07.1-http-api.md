# 7.1 HTTP API

> **Spec chapter:** Public HTTP/`HttpApi` contract for instance routes (Protocol groups plus Server host wiring).
> **Parent:** [7 Interface](../07-interface.md)
> **Index:** [README.md](../README.md)

**Files:** `packages/protocol/` (`@opencode-ai/protocol`), `packages/server/` (`@opencode-ai/server`)

This slice is the **public HTTP/`HttpApi` surface**: Effect `HttpApi` groups and error types in `@opencode-ai/protocol`, served by `@opencode-ai/server` (`HttpApiBuilder.layer`). Package homes and Core handler internals belong in [6.5 Server](06.5-server.md). Generated client trees (`src/generated`, `src/generated-effect`) are not the behavioral source of truth. This pass is retrospective of shipped code.

Runtime dependencies follow: Schema to Core and Protocol, then from Core and Protocol to Server. Client runtime code may depend on Schema and Protocol but never Core or Server; `sdk-next` composes Client, Core, and Server (`AGENTS.md`; `packages/protocol/package.json` depends on `@opencode-ai/schema`; `packages/server/package.json` depends on `@opencode-ai/core` and `@opencode-ai/protocol`).

After changing the public Protocol or Server `HttpApi`, `AGENTS.md` requires `bun run generate` from `packages/client` and forbids editing `src/generated` or `src/generated-effect` directly. Canonical home for workspace generate commands is 10.2. This chapter does **not** claim that `packages/protocol` or `packages/server` invoke `bun run generate`, `./packages/sdk/js/script/build.ts`, `generate:tailwind`, `generate:v2-oc2`, or `db:generate` / `drizzle-kit generate`.

## Behavior

### HttpApi composition

`makeApiFromGroup` adds groups in this order: `HealthGroup`, `LocationGroup` (location middleware), `AgentGroup` (location), `makeSessionGroup(sessionLocationMiddleware)`, `MessageGroup` (session-location), `ModelGroup` (location), `ProviderGroup` (location), `IntegrationGroup` (location), `CredentialGroup` (location), `makePermissionGroup(location, sessionLocation)`, `FileSystemGroup` (location), `CommandGroup` (location), `SkillGroup` (location), `eventGroup`, `PtyGroup` (location), `makeQuestionGroup(location, sessionLocation)`, `ReferenceGroup` (location), `ProjectCopyGroup` (location) (`packages/protocol/src/api.ts`).

`makePermissionGroup` and `makeQuestionGroup` apply location middleware only to endpoints added **before** `.middleware(locationMiddleware)`; session-scoped endpoints added afterward use `sessionLocationMiddleware` on the endpoint (`packages/protocol/src/groups/permission.ts`, `packages/protocol/src/groups/question.ts`).

Server `handlers` merges one `HttpApiBuilder.group` per group name (`packages/server/src/handlers.ts`).

### Endpoint catalog

Identifier and summary come from each endpoint’s `OpenApi.annotations`. Payload/query/success names are the Protocol symbols. `NoContent` is `HttpApiSchema.NoContent`. Success encodings are each endpoint’s Protocol `success` field; they are not uniformly `Location.response(…)`. Examples: `location.get` is `Location.Info`; `permission.saved.list` is `{ data: Array }`; `permission.saved.remove`, `credential.update`, `credential.remove`, `pty.remove`, and `projectCopy.remove` / `projectCopy.refresh` are `NoContent`; `projectCopy.create` is `ProjectCopy.Copy`.

`fs.read` success is `Schema.Uint8Array` via `HttpApiSchema.asUint8Array()`. The shipped handler is `handleRaw`: path after `/api/fs/read/` is `decodeURIComponent(pathname.slice(13))`; response is `HttpServerResponse.uint8Array(file.content, { contentType: file.mime })` (`packages/server/src/handlers/fs.ts`).

`session.events` success is `HttpApiSchema.StreamSse({ data: SessionEvent.Durable })`. `event.subscribe` success is `HttpApiSchema.StreamSse({ data: EventSchema })` where `EventSchema` is the union over `EventManifest.ServerDefinitions` plus a `server.connected` variant when that type is absent (`packages/protocol/src/groups/event.ts`).

`pty.connect` OpenAPI sets `"x-websocket": true` and documents query names `location[directory]`, `location[workspace]`, `cursor`, and `ticket`. Protocol success type is `Schema.Boolean`. The shipped handler is `handleRaw` (WebSocket upgrade) (`packages/protocol/src/groups/pty.ts`, `packages/server/src/handlers/pty.ts`).

### Location selection and middleware

Location-scoped groups attach `LocationMiddleware`. `ref` builds `Location.Ref` from:

- workspace: query `location[workspace]` or header `x-opencode-workspace`
- directory: query `location[directory]`, else `decodeURIComponent` of `x-opencode-directory` when that header is set, else `process.cwd()`

`decode` returns the original string when `decodeURIComponent` throws (`packages/server/src/location.ts`). The effect is then `locations.get(ref(request))`.

Session-scoped endpoints attach `SessionLocationMiddleware`. It decodes `route.params.sessionID` as `SessionV2.ID`. Decode failure yields `InvalidRequestError` with `message: "Invalid session ID"` and `field: "sessionID"`. Missing session row yields `SessionNotFoundError` with `message: \`Session not found: ${sessionID}\`` (`packages/server/src/middleware/session-location.ts`).

`LocationHandler` returns `Location.Info` from `Location.Service` (`packages/server/src/handlers/location.ts`). `response` (`packages/server/src/location.ts`) wraps a Core effect as `{ location: Location.Info, data }` only in handlers that call it: `agent.list`, `model.list`, `provider.list`, `provider.get`, `command.list`, `skill.list`, `reference.list`, `fs.list`, `fs.find`, `permission.request.list`, `question.request.list`, `integration.list`, `integration.get`, `integration.connect.oauth`, `integration.attempt.status`, `pty.list`, `pty.create`, `pty.get`, `pty.update`, `pty.connectToken`. It is not used for `permission.saved.list` / `permission.saved.remove`, `credential.update` / `credential.remove`, `projectCopy.*`, `fs.read`, `pty.remove` / `pty.connect`, or `integration.connect.key` / `integration.attempt.complete` / `integration.attempt.cancel`.

### Authentication

When `ServerAuth.required(config)` is false, `authorizationLayer` is identity (`packages/server/src/middleware/authorization.ts`).

When required, credentials come from:

1. Query `auth_token` (Base64 credential string), else
2. `Authorization` matching `/^Basic\s+(.+)$/i`

Decode uses `Encoding.decodeBase64String`. Missing `:` yields empty username and redacted empty password. `ServerAuth.authorized` requires matching `config.username` and redacted password equal to `config.password.value`.

Failure sets `www-authenticate` to `Basic realm="Secure Area"` and fails with `UnauthorizedError({ message: "Authentication required" })`.

If `hasPtyConnectTicketURL` is true (`pathname` matches `/^\/api\/pty\/[^/]+\/connect$/` **and** query `ticket` is non-empty), credential checks are skipped; the PTY connect handler consumes the ticket (`packages/protocol/src/groups/pty.ts`, `packages/server/src/middleware/authorization.ts`).

`ServerAuth.header` builds `Basic ${Buffer.from(\`${username}:${password}\`).toString("base64")}` using `credentials` or `process.env.OPENCODE_SERVER_PASSWORD` / `OPENCODE_SERVER_USERNAME` (username fallback `"opencode"`). No password → `undefined`. `headers()` returns `{ Authorization }` or `undefined` (`packages/server/src/auth.ts`).

### Session list cursor and history query

`SessionsCursor` is a branded string: `Encoding.encodeBase64Url` of JSON matching `SessionsCursorInput` (directory / project / all variants with `Session.ListAnchor`). `parse` fails with `"Invalid cursor"` on Base64 or JSON decode failure (`packages/protocol/src/groups/session.ts`). `session.list` maps parse failure to `InvalidCursorError({ message: "Invalid cursor" })` (`packages/server/src/handlers/session.ts`).

`SessionHistoryQuery` decodes `after` and `limit` via `Schema.NumberFromString` to `NonNegativeInt` and `SessionHistoryLimit` (`packages/protocol/src/groups/session.ts`).

`session.messages` rejects combined `cursor` and `order` with `InvalidCursorError({ message: "Cursor cannot be combined with order" })`. Cursor bytes are `base64url` JSON `{ id, order, direction }` (`packages/server/src/handlers/message.ts`). Default `order` is `"desc"`.

### Event SSE and PTY connect

`event.subscribe` is `handleRaw`. First SSE payload is `{ id: EventV2.ID.create(), type: "server.connected", data: {} }`, then `EventV2.allBounded(…, 256)`. Frames use SSE `event: "message"` and `JSON.stringify(Schema.encodeUnknownSync(OpenCodeEvent)(data))`. Heartbeats are `: heartbeat\n\n`. Response `contentType` is `text/event-stream` with headers `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`, `X-Content-Type-Options: nosniff` (`packages/server/src/handlers/event.ts`).

`pty.connectToken` requires header `x-opencode-ticket` equal to `1` **and** `isAllowedRequestOrigin(origin, host, cors)`. Otherwise `ForbiddenError({ message: "Invalid PTY connect token request" })`.

`isAllowedCorsOrigin` (`packages/server/src/cors.ts`): missing origin → allow; `http://localhost:` prefix; `http://127.0.0.1:` prefix; `oc://renderer` prefix (`input.startsWith`, same as `http://localhost:`); `tauri://localhost` / `http://tauri.localhost` / `https://tauri.localhost`; `/^https:\/\/([a-z0-9-]+\.)*opencode\.ai$/`; else `opts?.cors?.includes(input)`. `isAllowedRequestOrigin` also allows when `new URL(origin).host === host`.

`pty.connect` (`handleRaw`): missing PTY → `HttpServerResponse.empty({ status: 404 })`. If query `ticket` is present: origin check then `tickets.consume`; failure → `HttpServerResponse.empty({ status: 403 })`. Query `cursor` is used only when `Number(parsedCursor)` is a safe integer `>= -1`.
