# 10.1 Install

> **Spec chapter:** Shipped install surfaces for bins `opencode` and `lildax`, desktop Electron `main`, and workspace install scripts.
> **Parent:** [10 Operations](../10-operations.md)
> **Index:** [README.md](../README.md)

**Files:** `package.json`; `packages/opencode/bin/opencode`; `packages/opencode/script/postinstall.mjs`; `packages/opencode/script/publish.ts`; `packages/opencode/src/installation/index.ts`; `packages/opencode/src/cli/cmd/uninstall.ts`; `packages/cli/bin/lildax.cjs`; `packages/desktop/src/main/index.ts`; `packages/desktop/electron-builder.config.ts`

This slice is **install and launch packaging**, not CLI command semantics ([6.1 Agent CLI](06.1-agent-cli.md), [6.15 CLI](06.15-cli.md)) or desktop UI ([6.19 Desktop](06.19-desktop.md)). This pass is retrospective of shipped code.

Published npm names differ from workspace `package.json` `name` values. Workspace `opencode` is `private: true` (`packages/opencode/package.json`). Workspace `@opencode-ai/cli` has no `private` field (`packages/cli/package.json`). The npm wrapper package for `opencode` is published as `opencode-ai` (`packages/opencode/script/publish.ts`). The published wrapper for `lildax` keeps name `@opencode-ai/cli` (`packages/cli/script/publish.ts`).

## Behavior

### Workspace scripts

Root `package.json` `postinstall` runs `bun run --cwd packages/core fix-node-pty`. `prepare` runs `husky`. `trustedDependencies` includes `electron`, `esbuild`, `node-pty`, `protobufjs`, `tree-sitter`, `tree-sitter-bash`, `tree-sitter-powershell`, and `web-tree-sitter`.

`packages/opencode/package.json` `scripts.build` is `bun run script/build.ts`. `packages/cli/package.json` `scripts.build` is `bun run script/build.ts`. Desktop `predev` runs `bun run install-electron`, copies icons, `cd ../opencode && bun script/build-node.ts`, then `downloadCliToResources()` (`packages/desktop/scripts/predev.ts`). `prebuild` copies icons and metainfo, builds opencode node, and calls `downloadCliToResources()` only when `resolveChannel()` is `"dev"` (`packages/desktop/scripts/prebuild.ts`).

### `opencode` binary wrapper

The workspace launcher `packages/opencode/bin/opencode` (not shipped in `opencode-ai`) spawns a native binary, forwarding argv and signals `SIGINT`, `SIGTERM`, `SIGHUP` (`run`). Resolution order: `process.env.OPENCODE_BIN_PATH`, else `path.join(scriptDir, ".opencode")` if that path exists, else walk parents of the wrapper directory for `node_modules/<name>/bin/opencode` (Windows: `opencode.exe`). Published `opencode-ai` `bin` is only `./bin/opencode.exe`: the `publish.ts` placeholder or the postinstall native copy.

Platform package `name` values are `opencode-<platform>-<arch>` with `win32` mapped to `windows`. x64 without AVX2 prefers `*-baseline` first. Linux musl (Alpine `/etc/alpine-release` or `ldd --version` text containing `musl`) prefers `*-musl` names. AVX2: Linux `/proc/cpuinfo` token `avx2`; Darwin `sysctl -n hw.optional.avx2_0` stdout `1`; Windows `IsProcessorFeaturePresent(40)` via PowerShell.

Compiled platform packages are produced by `packages/opencode/script/build.ts` (`outfile` `dist/${name}/bin/opencode`, `preferUnplugged: true`). When `Script.release` is true, that script also writes `${name}.tar.gz` (linux) or `.zip` (else) and runs `gh release upload v${Script.version}`.

`packages/opencode/script/publish.ts` publishes each `dist/*/package.json` name, then the `opencode-ai` wrapper. Docker image `ghcr.io/anomalyco/opencode` is built for `linux/amd64,linux/arm64` when `Script.preview` is falsy. Non-preview also writes AUR `opencode-bin` (`install -Dm755 ./opencode` → `/usr/bin/opencode`) and Homebrew formula `opencode.rb` (`bin.install "opencode"`, `depends_on "ripgrep"`).

Published `postinstall.mjs` copies the matching optional-dep binary to `bin/opencode.exe` (hard link, else copy), `chmod 0o755`, and verifies with `opencode.exe --version` exit `0`. If `require.resolve` fails, it `npm install --ignore-scripts --no-save` that optional package into a temp prefix.

Until postinstall runs, `publish.ts` writes `bin/opencode.exe` as a script that prints that `opencode-ai`'s postinstall was not run (`--ignore-scripts` or pnpm skipping postinstall) and suggests `cd node_modules/opencode-ai && node postinstall.mjs`.

### `lildax` binary wrapper

`packages/cli/bin/lildax.cjs` uses the same spawn/signal/`OPENCODE_BIN_PATH` rules. Cached path is `.lildax`. Package names are `@opencode-ai/cli-<platform>-<arch>` with the same baseline/musl preference order. Native file is `lildax` / `lildax.exe`. `packages/cli/script/build.ts` writes `dist/cli-…/bin/lildax` and `package.json` `name` `@opencode-ai/${name}` where `name` is `cli-<os>-<arch>…`. Publish copies the CJS wrapper to `dist/@opencode-ai/cli/bin/lildax` (no postinstall script in the published wrapper `package.json`).

### Installation method, latest, and upgrade

`packages/opencode/src/installation/index.ts` `Installation.Service`:

`method()` returns `"curl"` when `process.execPath` contains `path.join(".opencode", "bin")` or `path.join(".local", "bin")`. Otherwise it runs package-manager list commands (npm/yarn/pnpm/bun global lists; `brew list --formula opencode`; `scoop list opencode`; `choco list --limit-output opencode`), preferring a manager whose name appears in `process.execPath`. A hit requires the listing output to include `opencode` (brew/choco/scoop) or `opencode-ai` (npm/yarn/pnpm/bun). Else `"unknown"`. `yarn` is detected here; `upgrade` has no `yarn` case.

`latest(method)`:

| Method | Source |
|--------|--------|
| `brew` core formula | GET `https://formulae.brew.sh/api/formula/opencode.json` → `versions.stable` |
| `brew` tap `anomalyco/tap/opencode` | `brew info --json=v2` → first formula `versions.stable` |
| `npm` / `bun` / `pnpm` | GET `{NpmConfig.registry(cwd)}/opencode-ai/${InstallationChannel}` → `version` |
| `choco` | Chocolatey OData `Id eq 'opencode' and IsLatestVersion` → `d.results[0].Version` |
| `scoop` | `https://raw.githubusercontent.com/ScoopInstaller/Main/master/bucket/opencode.json` → `version` |
| `curl` / `unknown` / default | GET `https://api.github.com/repos/anomalyco/opencode/releases/latest` → `tag_name` with leading `v` stripped |

`upgrade(method, target)`:

| Method | Command / action |
|--------|-----------------|
| `curl` | GET `https://opencode.ai/install`; pipe body to `bash` if `bash --version` returns text, else `sh`; env `VERSION=target` |
| `npm` | `npm install -g opencode-ai@${target}` |
| `pnpm` | `pnpm install -g opencode-ai@${target}` |
| `bun` | `bun install -g opencode-ai@${target}` |
| `brew` | `HOMEBREW_NO_AUTO_UPDATE=1`; tap path: `brew tap anomalyco/tap`, `git pull --ff-only` in `brew --repo anomalyco/tap`, then `brew upgrade <formula>`; core: `brew upgrade opencode` |
| `choco` | `choco upgrade opencode --version=${target} -y` |
| `scoop` | `scoop install opencode@${target}` |

`info()` returns `{ version: InstallationVersion, latest }`. `userAgent(client = "cli")` is `opencode/${InstallationChannel}/${InstallationVersion}/${client}`. `isPreview()` is `InstallationChannel !== "latest"`. `isLocal()` is `InstallationChannel === "local"`. `getReleaseType` compares `semver.major`/`minor` and returns `"major"` / `"minor"` / `"patch"`.

`InstallationChannel` and `InstallationVersion` are imported from `@opencode-ai/core/installation/version` (not in this slice’s allowed paths).

### `opencode uninstall`

`UninstallCommand` (`packages/opencode/src/cli/cmd/uninstall.ts`): command `uninstall`, describe `uninstall opencode and remove all related files`. Flags `--keep-config`/`-c`, `--keep-data`/`-d`, `--dry-run`, `--force`/`-f` default `false` (help snapshot `opencode uninstall --help`).

It logs `Installation method: ${method}`. Removal directories use `Global.Path.data|cache|config|state` from `@opencode-ai/core/global` (paths not in this slice’s allowed sources). `--keep-data` / `--keep-config` skip those directories. Cache and state are never kept by those flags.

For `curl`, it may record `process.execPath` as the binary and a shell rc that contains `# opencode` or `.opencode/bin`. After delete, curl installs are told to `rm "<binary>"` (and `rmdir` the bin dir if it includes `.opencode`); the process does not delete the running binary itself.

Non-`curl`/`unknown` package removal:

| Method | Command shown / run |
|--------|---------------------|
| `npm` | `npm uninstall -g opencode-ai` |
| `pnpm` | `pnpm uninstall -g opencode-ai` |
| `bun` | `bun remove -g opencode-ai` |
| `yarn` | `yarn global remove opencode-ai` |
| `brew` | `brew uninstall opencode` |
| `choco` | shown `choco uninstall opencode`; run `choco uninstall opencode -y -r` |
| `scoop` | `scoop uninstall opencode` |

`--dry-run` logs `Dry run - no changes made`. Without `--force`, confirm prompt is `Are you sure you want to uninstall?` with `initialValue: false`. Cancel logs `Cancelled`. `executeUninstall` uses `prompts.log.success("Thank you for using OpenCode!")`. The handler `prompts.outro` is `Done`.

Shell cleanup removes a line that is exactly `# opencode` plus the following line when it contains `.opencode/bin` or `fish_add_path`, and any `export PATH=` line containing `.opencode/bin` or `fish_add_path` containing `.opencode`.

### Desktop packaging and bundled CLI

`electron-builder.config.ts` `files` include `out/**/*` and `resources/**/*` and exclude `!resources/opencode-cli*`. `extraResources` copies `opencode-cli*` from `resources/` only when channel is `dev`. Native addon files copy from `native/` (`index.js`, `index.d.ts`, `build/Release/mac_window.node`, `swift-build/**`).

Prod deb/rpm also install hidden `resources/linux/opencode-desktop.desktop` → `/usr/share/applications/opencode-desktop.desktop` (`NoDisplay=true`, `Exec=/opt/OpenCode/ai.opencode.desktop %U`, `Icon`/`StartupWMClass` `ai.opencode.desktop`). Metainfo XML is installed as `/usr/share/metainfo/${appId}.metainfo.xml`.

Windows signing runs `script/sign-windows.ps1` only when `process.platform === "win32"` and `GITHUB_ACTIONS === "true"`.

`downloadCliToResources` installs `${cli.package}@0.0.0-next-16350` and copies `bin/opencode2` (`opencode2.exe` on win32) to `resources/opencode-cli` (`.exe` suffix on Windows).

### Desktop `main`

`packages/desktop/electron.vite.config.ts` compiles `src/main/index.ts` (and `sidecar.ts`) into the Electron main bundle. `packages/desktop/package.json` `main` is `./out/main/index.js`.

On start (`index.ts` `main`): `process.chdir(homedir())` (best-effort); `OPENCODE_DISABLE_EMBEDDED_WEB_UI=true`; single-instance lock (`app.requestSingleInstanceLock()` — failure `app.quit()`); `app.setAsDefaultProtocolClient("opencode")`; deep links via `opencode://` on `second-instance` argv and `open-url`. Unpackaged adds `--remote-debugging-port=9222`.

`setupAutoUpdater(stopSidecars)` then `updater.start()`; check every 10 minutes. `UPDATER_ENABLED` is false for unpackaged or `CHANNEL === "dev"`.

Sidecar: `OPENCODE_SIDECAR_V2 === "1"` uses `startBackgroundCli`. Packaged v2 copies the resource binary `opencode-cli` / `opencode-cli.exe` to `userData/cli/<sanitized version>/` (`installCli` in `background-cli.ts`), then `service status` / `service start` / `service get password`. Unpackaged uses the resources copy in place. Username emitted to the renderer is `"opencode"`. v1 listens on `127.0.0.1` with `OPENCODE_PORT` or an ephemeral port and HTTP basic user `"opencode"`.

`hasExistingAppState` (`install-state.ts`) is false for empty dirs and Electron `Local State` / `Crashpad`. It is true for `opencode.settings`, any `*.dat`, `window-state-*.json`, or a directory named `opencode`. `initializeOldLayoutEligibility` stores that once. First-launch onboarding is pending until store key `FIRST_LAUNCH_ONBOARDING_COMPLETE_KEY` is true; `finishFirstLaunchOnboarding(true)` mkdir `join(documents, "Default Project")`.

Non-macOS `window-all-closed` quits the app.

## Error handling

| Situation | Behavior | Source |
|-----------|----------|--------|
| Wrapper cannot resolve a binary | stderr: `It seems that your package manager failed to install the right version of the opencode CLI for your platform. You can try manually installing "<name>" or … package`; exit `1` | `packages/opencode/bin/opencode` |
| `lildax` wrapper miss | stderr: `It seems that your package manager failed to install the right lildax CLI package. Try manually installing "<name>" or … package`; exit `1` | `packages/cli/bin/lildax.cjs` |
| Spawn error | `console.error(error.message)`; exit `1` | both wrappers `run` |
| Child exit with signal | parent `process.kill(pid, signal)` | both wrappers |
| Child exit with code | `process.exit(code)` (`0` if code is not a number) | both wrappers |
| `postinstall.mjs` cannot place a working binary | throw / stderr `error.message`; exit `1`. Message: `It seems your package manager failed to install the right opencode CLI package. Try manually installing …` | `postinstall.mjs` `main` |
| Placeholder `opencode.exe` (no postinstall) | stderr lines including `Error: opencode-ai's postinstall script was not run.`; exit `1` | `publish.ts` placeholder |
| `upgrade` non-zero or missing result | `UpgradeFailedError` whose `stderr`/`message` is `Upgrade failed for ${method} (exit code ${code}).` (or without exit code). `choco` uses `not running from an elevated command shell`. Tests assert npm/curl failures do not echo command `stderr` containing secrets. | `Installation.upgradeFailure`, `installation.test.ts` |
| `upgrade` default / `yarn` | `UpgradeFailedError` `Unknown installation method: ${m}` | `Installation.upgrade` |
| `downloadCliToResources` unknown rust target | `CLI configuration not available for target '${target}'` | `getCurrentCli` |
| `nativeTarget` unsupported OS | `Unsupported platform: ${platform}/${arch}` | `packages/desktop/scripts/utils.ts` |
| Homebrew tap update without `GITHUB_TOKEN` | stderr `GITHUB_TOKEN is required to update homebrew tap`; exit `1` | `publish.ts` |
| Second desktop instance | `app.quit()` | `index.ts` |
| Sidecar v1 health timeout | log `sidecar health check failed`; does not fail the Effect | `index.ts` |
| Uninstall package-manager non-zero | spinner fail `Package manager uninstall failed: exit code ${code}`; choco elevated text → warn to run from elevated shell; else warn to run the command manually | `executeUninstall` |
| Uninstall dir `fs.rm` failure | collect `${label}: ${err.message}`; still prints success thank-you | `executeUninstall` |
| `updater-controller` `stop` throws during install | `install()` rejects; state stays `{ status: "ready", version }` | `updater-controller.test.ts` `returns to ready when installation cannot start` |
