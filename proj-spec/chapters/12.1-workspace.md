# 12.1 Workspace tests

> **Spec chapter:** Where workspace packages keep `*.test.*` / `*.spec.*` files and which `package.json` `scripts.test` commands run (or refuse) them.
> **Parent:** [12 Testing](../12-testing.md)
> **Index:** [README.md](../README.md)

**Files:** `package.json` (repo root); `packages/**/package.json`; test files matching `packages/**/*.{test,spec}.*`

This slice is the **workspace test layout**: root `test` refusal, per-package test scripts, and on-disk test locations. It does not specify product behavior asserted inside those tests. This pass is retrospective of shipped manifests and test paths.

## Construction / configuration

| Root `private` | `true` | `package.json` |

The root `scripts` object has no `test:*` keys besides `test`.

## Behavior

### Root test command

`bun run test` at the repo root runs `echo 'do not run tests from root' && exit 1` (`package.json` `scripts.test`). Tests are invoked from individual package directories via that package’s scripts (when present).

## Error handling

When `scripts.test` runs at the repo root, the shell command prints `do not run tests from root` and exits with status `1` (`package.json` `scripts.test`: `echo 'do not run tests from root' && exit 1`).

`@opencode-ai/app` `scripts.test` uses `&&` between `test:unit` and `test:browser`: if `test:unit` fails, `test:browser` is not started (`packages/app/package.json`).

`packages/app` `test:stability` likewise chains bun test and playwright with `&&`. `packages/opencode` `test:httpapi` chains three `httpapi-exercise.ts` invocations with `&&`.

Bun/`playwright` process exit codes for package `bun test` / `playwright test` scripts are not encoded in `package.json` beyond those `&&` / `exit 1` strings.
